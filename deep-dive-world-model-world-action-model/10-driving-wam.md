# 10 · 自动驾驶 WAM（D9）

> **核心问题**：驾驶和操作是同一个 WAM 吗？
> 骨架一样，但有三处结构性差异，其中最重要的一条是——**驾驶的未来本质上是多峰的**。
> 本篇解析这三条差异，梳理五篇代表工作，并用 Lab D9 量化“多模态未来”到底值多少。

---

## 1. 驾驶与操作的三点结构性差异

| 维度 | 机械臂操作 | 自动驾驶 |
|:---|:---|:---|
| **动作** | 关节 / 末端位姿，**本体相关** | **轨迹**（低维、连续、可直接监督），天然跨“本体” |
| **未来** | 物体动力学，基本确定 | **多峰**：行人可能过/停/退，他车可能让/抢 |
| **失败代价** | 任务失败，通常可重试 | 碰撞，不可重试 |
| **数据** | $10^3$–$10^5$ 条，采集贵 | $10^5$–$10^6$ clips，车上就有 |
| **评价** | 成功率（离散） | PDMS / EPDMS（开环）+ HD-Score（闭环） |

**第一行的含义很重要**：驾驶的动作是轨迹，所以 D7（动作表征与跨本体）在驾驶域**基本不是问题**——不同车型的轨迹都在同一个 $(x, y, \theta)$ 空间里。这是驾驶 WAM 比操作 WAM 进展更快的一个结构性原因。

**第二行是本篇的重点**：交互场景下，给定 ego 的动作，未来仍然多峰（因为他车的意图未知）。

---

## 2. 基准与指标

| 基准 | 类型 | 指标 |
|:---|:---|:---|
| **NAVSIM / NAVSIM-v2** | 开环规划 | PDMS、EPDMS |
| **HUGSIM** | **闭环**仿真 | HD-Score |
| **nuScenes / Bench2Drive** | 零样本迁移 | 各指标 |
| **PhysicalAI-Autonomous-Vehicles** | 大规模 | — |

**开环 vs 闭环的关键差别**：开环只评估“轨迹像不像人类开的”，闭环才评估“这么开会怎样”。WA-JEPA 在 HUGSIM 上**不做特化微调**就能拿 0.4462 HD-Score，含金量比开环数字高得多。

## 3. 五篇代表工作

### 3.1 DriveWAM：把视频 DiT 改成自回归 video-action policy

[DriveWAM (2605.28544)](https://arxiv.org/abs/2605.28544)（CUHK-Shenzhen + 滴滴）：Wan2.2-5B 视频 DiT → 自回归 video-action policy。

**三个技术点**：

1. **联合流匹配**：视频 token 与动作 token 放进统一时间序列，共享 transformer，联合 flow matching 目标。生成顺序是“**先生成未来视频潜变量，再从中解码 ego 动作**”——即 01 式 (2.2) 的 **scene-first / inverse dynamics** 路线。

2. **场景演化驾驶引导（scene-evolving driving guidance）**：冻结的 VLM 只用**因果可得**的上下文（最新观测、近期 ego 运动、路径指令），产出 **chunk 级别的语义意图**，通过**时间局部化的交叉注意力**注入。

 关键设计：每个未来 video-action chunk 收到**自己的**语义意图，同时保持整段自回归训练的因果结构。VLM 管语义，视频基座管稠密时间预测——职责分离得很干净。

3. **选择性 KV 记忆**：视频与动作各有一个**有界**记忆池，更新规则是“相关性-冗余度”选择，而不是按年龄淘汰。这让长视野 rollout 的 KV 缓存不随视野增长。

**Scaling 实验**：4k → 20k → 100k driving clips，性能**持续上升**。这是目前少见的、公开报告 WAM 数据 scaling 曲线的工作。

### 3.2 UNIVERSE：单 DiT + 模态解耦可见性掩码

[UNIVERSE (2607.05133)](https://arxiv.org/abs/2607.05133) 明确研究一个问题：**哪种架构更能把视频建模的收益迁移到轨迹生成？**

答案：单 DiT 优于 Two-DiT（NAVSIM 91.0 vs 89.6 PDMS）。

机制是 **Modality-Decoupling Visibility Mask**（详见 04 §2.4）：历史上下文两模态共享，未来视频 token 与未来轨迹 token 互不可见。两个好处——防泄漏 + 推理时可只跑轨迹（**4.3×**）。

### 3.3 SimWAM：视频只作训练信号

[SimWAM (2608.07468)](https://arxiv.org/abs/2608.07468)（华科 + 东风）是目前最“反直觉”也最实用的设计：

- 预训练视频专家 + 轻量动作专家，**无参数共享**，只通过统一注意力接口交互
- **隔离注意力掩码**让动作预测不依赖未来帧
- 训练完**整个视频分支丢掉**，留下自包含的规划器
- 再用 **RL 优化组合式驾驶奖励**（不止轨迹模仿）

NAVSIM **91.5 PDMS**，超过基于世界模型的 planner，延迟显著更低，零样本迁移 nuScenes。

它是 01 §2.2 判定边界第 ③ 条的教科书实现：**WAM 不一定要在推理时生成未来**。

### 3.4 WA-JEPA：潜空间路线

[WA-JEPA (2608.20974)](https://arxiv.org/abs/2608.20974) 已在 07 §4 详述。补充驾驶域的数字：NAVSIM-v2 **91.7 EPDMS**（超过最强端到端 +1.6、最强 WAM +1.3），HUGSIM **HD-Score 0.4462**（同协议最佳，且未做 HUGSIM 特化微调）。

### 3.5 MM-Future：多模态未来

[MM-Future (2609.20377)](https://arxiv.org/abs/2609.20377)（蔚来 + 中科大等，2026-09-17）是目前最新、也最有针对性的工作。

**它指出的问题**：

- **Cascade** 支持多模态 rollout（scene-first 或 action-first 都能采样多个），但影响是**单向**的——下游变量无法修正上游变量
- **Joint** 支持双向的 scene-action 交互，但通常只产生**一个**配对 rollout
- 所以：**cascade 有模式覆盖无双向耦合，joint 有双向耦合无模式覆盖**——而驾驶两个都要

**三个技术点**：

1. **配对假设初始化**：每个假设从一个结构化的动作先验 + 一个**独立的未来场景源**初始化
2. **模态感知扩散 Transformer**：场景与动作在一个假设内部**协同演化**（双向）
3. **MM-Tokens**：把多视角视频压缩成 **planning-oriented** 的表示，降低多模态 rollout 的成本（直接回应 07 §1 的计算浪费）
4. **未来条件化的候选打分器**：用共享历史上下文 + 配对的预测未来给轨迹候选排序

NAVSIM **94.0 PDMS / 91.5 EPDMS**，HUGSIM 零样本闭环 **32.3 HD-Score**。

## 4. 多模态未来的数学

### 4.1 为什么必须多模态

在交互场景下，即使**固定了 ego 的动作**，未来仍然是多峰的：

$$p(o' \mid o, a^{\text{ego}}) = \sum_{z} \underbrace{p(z \mid o)}_{\text{他车意图}} \cdot p(o' \mid o, a^{\text{ego}}, z)$$

其中 $z$ 是他车意图（让行 / 抢行 / 减速）。$z$ 不可观测，所以未来必然是多峰的。

### 4.2 单模态模型的失效

若模型只给一个未来，它（在 MSE 下）只能给期望：

$$\hat{o}' = \mathbb{E}[o' \mid o, a] = \sum_z p(z|o)\, \mathbb{E}[o' \mid o, a, z]$$

这个“平均未来”在物理上不存在（07 §3.2 的同一个机制）。更严重的是：**决策需要的是风险，不是期望**。

用期望做决策等价于风险中性，而驾驶需要**风险规避**：

$$a^* = \arg\max_a \ \underbrace{\mathrm{CVaR}_\alpha\Big(J(o', a)\Big)}_{\text{最坏 } \alpha \text{ 分位}} \quad \text{而不是} \quad \arg\max_a \mathbb{E}\big[J(o', a)\big]$$

**只有拿到多个未来假设，才能算 CVaR/最坏情况。** 这是多模态未来不可替代的数学理由。

### 4.3 Lab D9：多模态未来值多少

场景：无信号路口，ego 与他车抢同一个冲突点。他车类型（让行型 / 抢行型）**各 50% 且不可观测**，ego 动作是“抢行”或“让行”。碰撞判定为到达冲突点的时间差小于安全间隙 $\tau$。所有场景参数（距离、速度、$\tau$）随机采样，20000 次。

```
== Lab D9: 给定动作后未来仍多峰 —— 单模态 vs 配对多模态 ==
  场景: 随机距离/速度/安全间隙; 他车类型(让行/抢行)未知, 各 50%
  ego 动作: 抢行(v=2.5) / 让行(v=0.8)

  决策方式                                 真实碰撞率          平均通过时间
  ------------------------------------------------------------
  单模态(期望未来)                            0.149            4.79
  多模态(最坏情况评估)                          0.000            7.19

  对照: 全知 oracle(知道他车类型)
  oracle                               0.000            5.61
```

三条结论：

1. **单模态的代价是碰撞率 14.9%**。这不是小数目——在驾驶场景这是完全不可接受的。原因是“平均的他车行为”让 ego 误判某些间隙是安全的。

2. **多模态把碰撞率降到 0**，代价是通行时间从 4.79 涨到 7.19（**+50%**）。这是“不知道他车意图”必须付的保守性代价。

3. **Oracle（知道他车类型）能同时拿到 0 碰撞和 5.61 的时间**。所以：

$$\underbrace{7.19 - 5.61 = 1.58}_{\text{多模态与 oracle 的差距}} = \text{意图不确定性的残余代价}$$

 这给出一个明确的改进方向：**降低 $z$ 的不确定性**（更好的意图预测），而不是把轨迹规划做得更精细。这与 MM-Future 的“结构化动作先验 + 独立未来场景源”设计是一致的——它显式地在建模 $p(z)$。

### 4.4 与 MM-Future 的对应

| Lab D9 的概念 | MM-Future 的组件 |
|:---|:---|
| 他车意图 $z$（多峰来源） | 独立的未来场景源 |
| ego 动作先验 | 结构化的动作先验 |
| 每个假设内的 scene ↔ action 协同 | 模态感知 DiT 的双向交互 |
| 最坏情况评估选动作 | 未来条件化的候选打分器 |

## 5. 驾驶 WAM 对照表

| 工作 | 架构 | 生成顺序 | 推理时生成视频? | 关键数字 |
|:---|:---|:---|:---|:---|
| [DriveWAM](https://arxiv.org/abs/2605.28544) | Wan2.2-5B → AR policy | scene-first（先未来后动作） | 是 | 4k→100k clips scaling；~0.9 s/4 s chunk |
| [UNIVERSE](https://arxiv.org/abs/2607.05133) | 单掩码调制 DiT | 联合 | 可选（4.3× 只跑轨迹） | 91.0 PDMS |
| [SimWAM](https://arxiv.org/abs/2608.07468) | 视频专家 + 动作专家（隔离掩码） | 联合训练，动作直接预测 | **否**（分支丢弃） | 91.5 PDMS；RL |
| [WA-JEPA](https://arxiv.org/abs/2608.20974) | V-JEPA 潜空间 | 潜空间流匹配 | 否（潜空间） | 91.7 EPDMS；HD-Score 0.4462 |
| [MM-Future](https://arxiv.org/abs/2609.20377) | 多模态配对 + 模态感知 DiT | 多模态联合 | 是（MM-Tokens 压缩） | 94.0 PDMS / 91.5 EPDMS；32.3 HD-Score |

**读法**：五篇工作恰好覆盖了 D3（联合 vs cascade）、D6（潜空间）、D8（效率）、以及本篇的多模态未来。驾驶域是这个领域的**最佳试验场**——数据量足够做 scaling 研究，动作空间简单，但未来足够复杂。

## 6. 收敛度与未解决

**已收敛**：
- 视频基座 → 自回归 video-action policy 的转换方式（联合流匹配）
- 推理时可丢弃视频分支（SimWAM、UNIVERSE 都这么做）
- 多模态未来的必要性（Lab D9：单模态碰撞率 14.9%）

**未解决**：
1. **模式数量 $K$ 怎么选**？Lab D9 只用了 2 个模式。真实场景的模式空间是连续的，$K$ 取多大？取小了漏风险，取大了算不起。MM-Future 没有报告 $K$ 的消融。
2. **闭环评测做得太少**。绝大多数工作只报 NAVSIM 开环 PDMS/EPDMS。开环高不代表闭环好——WA-JEPA 和 MM-Future 报 HUGSIM 是加分项，但仍是少数。
3. **开环指标与真实安全性的相关性未验证**。PDMS 高的模型真的更安全吗？这本质上就是 D5 的问题（排序 vs 绝对准确率），在驾驶域更严重，因为失败代价不对称。
4. **意图不确定性没有显式建模**。Lab D9 显示残余代价 1.58 全部来自 $z$ 的不确定性，但主流方法都是隐式处理。

---

## 7. 要点

1. 驾驶的**动作是轨迹**，所以跨本体问题基本不存在——这是它比操作进展快的结构性原因（§1）。
2. 五篇代表工作覆盖了联合 vs cascade、潜空间、效率、多模态未来四条主线（§3、§5）。
3. **多模态未来不可替代，因为决策需要的是风险（CVaR）不是期望**（§4.2）。
4. Lab D9：单模态碰撞率 **14.9%** vs 多模态 **0%**，代价是通行时间 +50%；与 oracle 的残余差距 1.58 全部来自**意图不确定性**（§4.3）。
5. 改进方向是**降低他车意图的不确定性**，不是把轨迹规划做得更精细（§4.3③）。
