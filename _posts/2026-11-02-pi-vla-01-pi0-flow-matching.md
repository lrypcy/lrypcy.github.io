> **系列导航**：这是 π 系列具身模型深潜的第 1 篇。系列按**问题**组织而不是按发布时间：动作怎么表示（01 π0 / 02 FAST / 03 KI）→ 长程任务怎么拆（04 Hi Robot / 05 π0.5）→ 延迟怎么吃掉（06 RTC）→ 怎么从经验里学（07 RECAP / 08 RLT）→ 记忆与条件（09 MEM / 10 π0.7）。本篇是全系列的地基：后面所有篇目共用的符号（动作块 $$\mathbf{A}_t$$、观测 $$\mathbf{o}_t$$、速度场 $$v_\theta$$）都在这里立起来。

> **TL;DR**
>
> * **核心问题与结论**：VLA 要在几十赫兹上输出连续动作块，语言模型只会出离散 token。π0 的做法是把动作块建模成一条从噪声到数据的**直线概率路径**，用条件流匹配训练一个 300M 的 action expert 去拟合路径上的速度场，主干仍是 3B 的 PaliGemma。目标函数只有一项：让预测速度逼近 $$\epsilon-\mathbf{A}_t$$。
> * **关键证据**：条件流匹配平方损失的最优解就是边际速度场 $$v^*=(x-\mathbb E[x_0\mid x_t])/t$$。合成双峰探针上，只用样本对 $$(\epsilon,x_0)$$ 做核回归复算，与解析场在三个时间点上分别差 0.0139 / 0.0208 / 0.0259（实验 A）。
> * **适用边界与代价**：实验 B 显示 10 步 Euler 只是一阶方法，10→50 步误差仍降 4.22 倍——10 步是成本点不是收敛点；1 步会让 36.92% 的样本选错模态。$$\mathrm{Beta}(1.5,1)$$ 偏噪声端，等效样本数只剩 0.7507（实验 C）。
> * **系列定位**：解决“动作怎么连续地生成”；它不解决语言跟随衰减（03 KI）、长程任务分解（04/05）、推理延迟（06）与从经验中改进（07/08）。

## 1. 一个策略要同时满足三个互相打架的要求

把机器人控制写成条件分布，问题看起来很干净：给定观测 $$\mathbf{o}_t$$，输出未来一段动作

$$
\mathbf{A}_t=[\mathbf{a}_t,\mathbf{a}_{t+1},\ldots,\mathbf{a}_{t+H-1}]
$$

π0 取 $$H=50$$、控制频率最高 50 Hz，也就是一个动作块对应**一秒**的真实时间。观测是

$$
\mathbf{o}_t=[\mathbf{I}^1_t,\ldots,\mathbf{I}^n_t,\ell_t,\mathbf{q}_t]
$$

其中 $$\mathbf{I}^i_t$$ 是 2 到 3 路相机的图像，$$\ell_t$$ 是语言指令的 token 序列，$$\mathbf{q}_t$$ 是关节角。这个设定同时压了三个要求，而它们互相打架：

**第一，动作分布是多模态的。** 桌上有一块抹布，可以抓左边也可以抓右边；两个都对的策略在参数空间里是双峰的。用单峰分布（比如对角高斯）去拟合双峰，最小化平方损失的最优解是**均值**——一个两边都不像的动作。这不是优化不充分，是目标函数选错了。

**第二，频率高。** 50 Hz 意味着每个控制周期只有 20 ms 的预算，而模型是十亿参数级的。如果生成一个动作块要 300 ms，就必须让“算”和“动”重叠，这是第 06 篇 RTC 的全部动机。

**第三，跨本体。** 单臂、双臂、移动底盘的动作维度不一样，语义空间也不一样（关节角 vs 末端位姿）。同一个模型要能吃下这些，就必须让动作在表示层就被统一，而不是在输出层拼接。

π0 对这三个要求的回答分别是：用**流匹配**替代单峰回归（多模态）、用**动作块 + 并行去噪**替代逐 token 自回归（频率）、用**每维归一化到 [-1,1]** 替代统一物理量纲（跨本体）。三条里最核心的是第一条，其余两条都挂在它上面。

**$$H=50$$ 这个数是“反应性”与“推理次数”的直接兑换。** 块越短，策略对环境变化的反应越快，但每秒要推理的次数越多：$$H=50$$ 在 50 Hz 下是 1 秒、每秒推理 1 次；$$H=10$$ 是 0.2 秒、每秒推理 5 次。如果单次推理要 300 ms（第 06 篇给的实际量级），5 Hz 就直接崩掉。反过来块太长，一个块内部要覆盖越来越长的时序一致性，这种样本在数据里稀少，而且块内一旦走错，得等整块执行完才能纠正。1 秒是在“推理频率不超过 1 Hz”这个约束下能取的最大块长——它不是一个关于动作复杂度的超参，是一个关于延迟预算的超参。这一点在后面几篇里会反复出现：π0 的很多设计选择，真正的约束条件都是延迟，不是精度。

这三个要求在实现上是两两冲突的，冲突点值得单独列出来，因为后面每一篇本质上都是在给其中一对解耦：

| 想满足 | 会牺牲 | 机制 |
| --- | --- | --- |
| 多模态动作分布 | 延迟 | 需要迭代采样（多步积分）才能表达多峰 |
| 高频控制 | 块间连续性 | 块内并行去噪 → 块边界处新块与旧块可能不兼容 |
| 跨本体 | 精度 | 归一化抹平量纲，也抹平了不同本体的细微尺度差异 |

π0 只解决了第一行（用 10 步而不是上百步把采样代价压下来），第二行留给 06 篇 RTC 的 inpainting，第三行的代价在 07 篇的精度任务上暴露出来。

后文的符号统一如下：

| 符号 | 含义 | 备注 |
| --- | --- | --- |
| $$\mathbf{A}_t$$ | 长度为 $$H$$ 的动作块 | 下标 $$t$$ 是机器人时间步 |
| $$\mathbf{o}_t$$ | 观测（图像 + 语言 + 本体状态） | |
| $$\tau$$ | 流匹配时间，$$\tau\in[0,1]$$ | 论文约定 $$\tau=1$$ 是数据 |
| $$\mathbf{A}_t^{\tau}$$ | 加噪后的动作块 | |
| $$\epsilon$$ | 标准高斯噪声 | |
| $$v_\theta$$ | 网络预测的速度场 | |
| $$\mathbf{u}$$ | 回归目标（条件速度） | |
| $$v^*$$ | 边际速度场（理论最优解） | |

> 时间方向有个坑：**论文和官方开源实现的 τ 是反的**。论文写 $$\mathbf{A}_t^\tau=\tau\mathbf{A}_t+(1-\tau)\epsilon$$（τ=1 是数据），openpi 写 `x_t = t * noise + (1 - t) * actions`（t=1 是噪声），源码注释原文是 “yes, this is the opposite of the pi0 paper, and I'm sorry.”。本篇公式一律用论文方向（$$\tau=1$$ 是数据），引用源码时标注它自己的变量名。

## 2. 动作表示的三条路，以及各自的账

在 π0 之前，VLA 输出动作的主流做法是**逐维逐时间步分箱**：把每一维动作的取值范围切成 $$N$$ 个均匀 bin（常见 $$N=256$$），每一步动作变成 $$d$$ 个 token。一个动作块就是

$$
\mathcal{T}(\mathbf{a}_{1:H})=[T_{1,1},\ldots,T_{1,d},\ldots,T_{H,1},\ldots,T_{H,d}]
$$

token 数 $$H\cdot d$$。对 7 维、50 步的动作块，这是 350 个 token，而且**相邻 token 高度相关**——50 Hz 采样下，相邻两帧的关节角差异极小，模型要做的是从已经预测出的 349 个 token 里“猜”第 350 个，信息量近乎为零。这就是 FAST 那篇论文里分箱方案随采样频率升高而突然崩掉的机制：不是数据变复杂了，是表示把信息摊薄了。

π0 选了第二条路：**连续生成**。它不去预测 token，而是直接学一个把噪声搬到动作块上的变换。这条路本身不新（扩散策略早就这么干），π0 的贡献在于把“生成模型”和“预训练 VLM”接在一起时的那套具体接法。

三条路的账摆在一起是这样：

| 表示 | 训练目标 | 推理成本 | 精度上限 | 主要失败模式 |
| --- | --- | --- | --- | --- |
| 分箱 + 自回归 | 交叉熵 | $$H\cdot d$$ 次解码 | 受 bin 分辨率限制 | 高频下 token 相关性强，退化成复制上一帧 |
| 扩散（DDPM 式） | 噪声预测 | 数十到上百步 | 高 | 步数多，延迟大 |
| 流匹配（π0） | 速度回归 | 10 步 | 高 | 一阶积分器，少步数时选错模态 |

差别不在“网络结构”，在**概率路径的形状**。扩散的路径是弯曲的（方差保持或方差爆炸的 SDE 解），要从噪声走到数据得沿着曲线走很多小步；流匹配可以指定一条**直线**，直线上的速度是常数，一步就能走完一大段——代价是这条直线是“每个样本各自指向自己”的，边际场仍然弯曲，所以还是需要几步。这句话是整篇的技术核心，第 5、7 节会把它算清楚。

路径形状的差别有一个很干脆的判据：**看条件轨迹的二阶导**。流匹配的单条条件轨迹是

$$
\mathbf{A}_t^\tau=\tau\mathbf{A}_t+(1-\tau)\epsilon\ \Longrightarrow\ \frac{\mathrm{d}^2\mathbf{A}_t^\tau}{\mathrm{d}\tau^2}=\mathbf{0}
$$

二阶导恒为零。而 DDPM 的轨迹 $$\mathbf{x}_\tau=\sqrt{\bar\alpha_\tau}\mathbf{x}_0+\sqrt{1-\bar\alpha_\tau}\epsilon$$ 里，$$\sqrt{\bar\alpha_\tau}$$ 是 τ 的非线性函数，二阶导不为零。

这个差别决定了误差从哪来。对 Euler 而言，单条**条件**轨迹上的离散化误差正比于二阶导：流匹配的条件轨迹是直线，若知道条件场，一步就能精确到达；所以它的全部误差只来自一件事——推理时手上只有边际场，而边际场不是直线。DDPM 则要同时吃两笔误差：边际场的非线性 + 条件轨迹本身的弯曲。这就是“流匹配能 10 步、扩散常常要几十步”的真实原因，不是“流匹配更先进”，是**它把一笔误差提前消掉了**。

一个常见的疑问：动作块内部强相关，为什么采样噪声是各维独立的？因为路径的定义只约束端点之间的插值，不要求噪声匹配数据的相关结构。独立性是构造上的便利——它让 $$q(\mathbf{A}_t^\tau\mid\mathbf{A}_t)$$ 保持各向同性高斯，采样和反解都变成逐元素的乘加。相关性由边际场承担：网络看到的 $$\mathbf{A}_t^\tau$$ 已经带着数据的结构（因为插值里有一半是真实动作），它要学的是“这个带结构的模糊块该往哪个方向走”。把噪声也做成相关的，收益是零、代价是反解变复杂，所以没人这么做。

## 3. 网络：一个 transformer，两套权重

π0 的骨架沿用 Transfusion 的思路：一个 transformer，同时用两种损失训练两种 token——离散 token（语言）走交叉熵，连续 token（动作）走流匹配。在此之上加了一个改动：**给机器人相关的 token 单独一套权重**。

具体配置（论文附录 A-B）：

| 部分 | 配置 | 参数量 |
| --- | --- | --- |
| VLM 主干 | PaliGemma（Gemma 2B 语言模型）：width 2048，depth 18，mlp_dim 16384，18 个 head，1 个 KV head，head_dim 256 | 3B |
| action expert | width 1024，mlp_dim 4096 | ~300M |
| 合计 | | 3.3B |

两套权重只在 self-attention 层交互，其余各算各的。这个设计在论文里被类比成“两个专家的混合”：图像和语言 token 路由到主干，本体状态和动作 token 路由到 action expert。由于交互只发生在 attention，两个专家的 width 和 mlp_dim **不必相同**——这正是 action expert 能被缩到 1024 宽的原因。

这里要分清它和标准 MoE 的差别：**路由是硬编码的**，按 token 的类型分，不存在学习出来的 router，也没有负载均衡损失。标准 MoE 里 router 要给每个 token 算一组专家权重、再加辅助损失防止塌缩；π0 的结构里这些统统没有，因为“这个 token 是图像还是动作”是已知的，不需要猜。代价是专家数被锁死在 2，且不能按输入动态分配算力。收益是训练稳定——MoE 最难调的两件事（路由塌缩、专家不均衡）在这套结构里根本不出现。

为什么要把 action expert 做小？因为推理时它要被调用 10 次（每个去噪步一次），而主干只前向一次。主干的开销是常数，action expert 的开销乘 10。把它压到主干的四分之一宽，这十次的开销才不会变成主导项。第 9 节会把这个账算成 token·次。

主干本身为什么是 3B 而不是 7B？论文的说法很直白：PaliGemma 的“相对小的尺寸对实时控制有用”。也就是说这个尺寸是**被延迟预算选的，不是被精度选的**。这条约束在后面几篇里只会越来越紧：π0.5 仍是 3B，到 π0.6 提到约 5B（4B 的 Gemma + 860M 的 action expert），同样的十步推理就更贵，于是才有第 06 篇把“算”和“动”重叠起来的动机。模型变大和实时性之间的矛盾，是这条系列里唯一贯穿始终的矛盾。

还有个容易忽略的细节：**动作块的时间步信息怎么进网络**。π0 不用 AdaLN（那是 DiT 的做法），而是把加噪动作 $$\mathbf{a}^\tau_{t^{\prime}}$$ 和流时间 $$\tau$$ 的正弦编码拼起来过一个小 MLP：

$$
\mathbf{e}=W_3\cdot\mathrm{swish}\big(W_2\cdot\mathrm{concat}(W_1\cdot\mathbf{a}^\tau_{t^{\prime}},\ \phi(\tau))\big)
$$

其中 $$\phi:\mathbb R\to\mathbb R^w$$ 是正弦位置编码。也就是说，流时间不是一个全局的调制信号，而是**每个动作 token 自己的输入特征**。代价是 50 个 token 各自带一份时间编码（冗余），收益是实现简单、且和 prefix 的 KV cache 天然兼容——第 9 节会看到这一点有多重要。

一个对照值得记住：同一篇论文里的 π0-small（470M，不用 VLM 初始化）把这些都换掉了——语言用 DistilBERT 编码、action expert 改成 cross-attend 观测编码器、时间用 AdaLN-Zero 注入。在 5 个任务的评测上，π0 的平均分是 0.971 / 0.875 / 1.000 / 0.786 / 0.750，π0-small 是 0.443 / 0.333 / 0.500 / 0.271 / 0，OpenVLA 与 Octo 在多数任务上是 0。**同一套流匹配目标，换个主干就差一倍以上**——这组数字说明“连续动作怎么生成”和“语义先验从哪来”是两个独立的杠杆，π0 只解决了前者。

## 4. 掩码：一个 cumsum 式子表达三块结构

π0 的序列是三段拼接：图像 + 语言（prefix）、本体状态（1 个 token）、动作块（50 个 token）。三段之间的可见性不是随便定的，而是由一张掩码精确控制。论文只说“action expert 用全双向掩码”，源码里的实现比这句话具体。

`make_attn_mask` 用累积和把任意分块掩码压成一个式子：

```python
cumsum = jnp.cumsum(mask_ar, axis=1)
attn_mask = cumsum[:, None, :] <= cumsum[:, :, None]
```

`mask_ar` 的语义是“这个位置是否开启新块”：置 1 表示它是新块的起点、后面的 token 不能回头看它之前的内容；置 0 表示它和前一个 token 同块、可以互看。拼接时 prefix 全置 0（整块双向）、state 置 1（独立成块）、第一个 action 置 1 而其余 action 置 0（50 个动作 token 互为同块）。于是掩码长这样：

```text
11111111 000000          <- prefix 8 个 token，内部全双向
111111111 00000          <- state 那 1 行：能看到全部 prefix 和自己
11111111 111111          <- 以下 5 行是 action：能看到 prefix + state + 全部 action
11111111 111111
11111111 111111
11111111 111111
11111111 111111
```

实验 D 把这张表逐格核过：prefix 内部全 1、prefix 看不到 state 和 action、state 看得到 prefix 但看不到 action、action 之间全双向。可 attend 的位置数是 143，与闭式 $$8^2+9+5\times14$$ 对上。

这个结构有两个直接后果，后面两节都要用：

1. **prefix 的表示不依赖动作**。动作 token 只在最后一跳读 prefix，反过来不成立。第 9 节的 KV cache 复用就建立在这一点上。
2. **动作 token 之间是全双向的**。50 个动作在一次前向里同时去噪，不是逐 token 生成——这是“并行去噪”能成立的前提，也是它和自回归 VLA 在推理成本上分道扬镳的地方。

还有个容易漏掉的点：**动作的时序信息不在掩码里**。掩码全双向，意味着第 k 个动作和第 k+1 个动作在结构上完全对等，谁前谁后不由可见性决定，只能由 position id 表达（`positions = cumsum(mask) - 1`）。这和因果掩码的差别很大：因果结构里“方向”是免费得到的，双向结构里模型必须从位置编码里学出“50 个 token 对应 1 秒内的先后”。代价是位置编码的分辨率要撑得住 20 ms 的时间差；收益是同一套 attention 代码既能跑双向的图像 patch，又能跑有顺序的动作序列，不需要为两种可见性写两套 kernel。

## 5. 训练目标：为什么线性路径让条件速度与 τ 无关

要建模 $$p(\mathbf{A}_t\mid\mathbf{o}_t)$$，流匹配的做法是先指定一族从噪声到数据的**概率路径**，再让网络去拟合沿路径的速度场。π0 选的是最简单的线性-Gaussian 路径：

$$
q(\mathbf{A}_t^\tau\mid\mathbf{A}_t)=\mathcal{N}\big(\tau\mathbf{A}_t,\ (1-\tau)^2\mathbf{I}\big)
$$

等价地写成采样式：

$$
\mathbf{A}_t^\tau=\tau\mathbf{A}_t+(1-\tau)\epsilon,\qquad \epsilon\sim\mathcal{N}(\mathbf{0},\mathbf{I})
$$

$$\tau=0$$ 时是纯噪声，$$\tau=1$$ 时是数据。这条路径上的“速度”是导数 $$\mathrm{d}\mathbf{A}^\tau/\mathrm{d}\tau=\mathbf{A}_t-\epsilon$$，但训练时用的是反号形式——把噪声指向数据的位移记成

$$
\mathbf{u}(\mathbf{A}_t^\tau\mid\mathbf{A}_t)=\epsilon-\mathbf{A}_t
$$

负号只是方向约定，不影响结论。关键是：**这个条件速度不依赖 τ**。因为路径是直线，从 $$\epsilon$$ 到 $$\mathbf{A}_t$$ 的位移在整条路上恒定。这就是流匹配比扩散“便宜”的根源——扩散的条件噪声 $$\epsilon$$ 在不同时刻的信噪比不同，网络要同时学“往哪走”和“走多远”；直线路径把“走多远”变成了常数，网络只需要学“往哪走”。

于是训练目标退化成一次最小二乘：

$$
L^{\tau}(\theta)=\mathbb{E}_{p(\mathbf{A}_t\mid\mathbf{o}_t),\,q(\mathbf{A}_t^\tau\mid\mathbf{A}_t)}\big\lVert \mathbf{v}_\theta(\mathbf{A}_t^\tau,\mathbf{o}_t)-\mathbf{u}(\mathbf{A}_t^\tau\mid\mathbf{A}_t)\big\rVert^2
$$

实践上就是三步：采一批真实动作块、采一批高斯噪声、在随机的 $$\tau$$ 上线性插值，然后让网络回归两者之差。没有对抗、没有重要性采样、没有 log-likelihood。

有个跨本体的细节藏在一个 `axis` 里。JAX 参考实现的损失是 `jnp.mean(jnp.square(v_t - u_t), axis=-1)`——对动作维度**求平均**而不是求和。原因很实际：不同本体的动作维度差很多（从 6 维的单臂到 18 到 19 维的移动操作），求和会让高维本体在总损失里占更大份额，等于给数据混合偷偷加了一个与维度成正比的权重。求平均把每个样本拉回等权。这个选择不影响单本体训练，但直接影响混训时的有效配比，而跨本体正是 π0 的核心卖点。

openpi 同时维护两套实现，这一行在两套里的写法不同、结果相同，值得单独记一笔：

| 路径 | 文件 | 写法 | 归约发生地 |
| --- | --- | --- | --- |
| JAX（官方主线） | `src/openpi/models/pi0.py` | `jnp.mean(jnp.square(v_t - u_t), axis=-1)` | 模型内，输出形状 (b,)；`scripts/train.py` 再 `jnp.mean` |
| PyTorch（官方移植） | `src/openpi/models_pytorch/pi0_pytorch.py` | `F.mse_loss(u_t, v_t, reduction="none")` | 模型外，输出 (b, H, d)；`scripts/train_pytorch.py` 里 `loss = losses.mean()` |

两边的差别只是“先对动作维平均再对 batch 平均”和“一次全平均”。因为动作已被 `PadStatesAndActions` 零填充到固定的 `action_dim=32`、`action_horizon=50` 也固定，每个样本的元素个数相同，所以两种归约**数值完全等价**。但填充有一个副作用：7 维本体的那 25 个填充维也被算进分母，每条真实维的梯度权重是 $$1/32$$ 而不是 $$1/7$$。这不是 bug（所有本体同等缩放，相对配比不变），但改 `action_dim` 就等于改有效学习率，调参时要连着看。

这里有一个必须交代清楚的问题：**训练时用条件速度 $$\mathbf{u}$$，推理时没有 $$\mathbf{A}_t$$ 可看，网络学到的是什么？** 答案是边际速度场——对所有能走到同一个 $$\mathbf{A}_t^\tau$$ 的数据点取条件期望。下一节把它算出来。

## 6. 最优解是边际速度场

平方损失的最优解是条件期望，这一步不需要任何假设：

$$
v^*(\mathbf{x},\tau)=\mathbb{E}\big[\mathbf{u}\mid \mathbf{A}_t^\tau=\mathbf{x}\big]
$$

把 $$\mathbf{u}=\epsilon-\mathbf{A}_t$$ 代进去，再用 $$\epsilon=(\mathbf{x}-\tau\mathbf{A}_t)/(1-\tau)$$ 消掉 $$\epsilon$$：

$$
v^*(\mathbf{x},\tau)=\frac{\mathbf{x}-\mathbb{E}[\mathbf{A}_t\mid\mathbf{A}_t^\tau=\mathbf{x}]}{1-\tau}
$$

这个式子的信息量在于：**它把一个“生成模型”问题变成了一个“条件期望估计”问题**。网络实际在学的，是“看到当前这幅模糊的动作，数据大概长什么样”，然后用残差除以剩余噪声比例换算成速度。这也解释了为什么 τ 靠近 1 时数值会炸——分母趋于 0，而分子也趋于 0，两者相除的极限要靠数据分布的形状撑住。

顺带回答一个很容易卡住的问题：既然边际场有解析形式，为什么不直接算它、跳过训练？因为式子里的 $$\mathbb{E}[\mathbf{A}_t\mid\mathbf{A}_t^\tau=\mathbf{x}]$$ 需要 $$\mathbf{A}_t^\tau$$ 的边缘密度

$$
p_\tau(\mathbf{x})=\int p(\mathbf{x}\mid\mathbf{A}_t)\,p(\mathbf{A}_t)\,\mathrm{d}\mathbf{A}_t
$$

而 $$p(\mathbf{A}_t)$$ 正是我们想学的数据分布。**要算边际场就得先知道答案**。所以只能用样本对 $$(\epsilon,\mathbf{A}_t)$$ 做回归，让网络把“条件期望”这个积分隐式地学进参数里——这正是回归目标写成条件速度而不是边际场的原因，也是“训练用条件量、推理用边际量”这个看似矛盾之处并不矛盾的地方。

在合成探针上这条式子是可以独立复核的：取一维双分量高斯混合（权重 0.35 / 0.65，中心 -1.2 / 1.0，标准差 0.25 / 0.50），它模拟“同一观测下两种可行动作”。解析地算 $$v^*$$ 只需要高斯混合的责任度加权；另一条路是**只用样本对** $$(\epsilon,\mathbf{A}_t)$$ 做核回归，完全不碰解析式。两条路在 $$\tau=0.2/0.5/0.8$$ 三个点上的最大偏差分别是 0.0139 / 0.0208 / 0.0259（实验 A），差值量级就是核回归自己的偏差与方差。这一组以及后文所有“实验 X”的结果都在 [`experiments/pi-vla/pi0-flow-matching/`](https://github.com/lrypcy/ipynbs/tree/d358500/experiments/pi-vla/pi0-flow-matching)，notebook 里代码与输出并排。

两个端点的行为值得单独记一笔：

- $$\tau\to1$$：$$v^*(\mathbf{x},1)=\mathbf{x}-\mathbb{E}[\mathbf{A}_t]$$。噪声端的场就是“把数据均值减掉”，与具体数据点无关。这一条是下一节“1 步塌缩”的直接原因。
- $$\tau\to0$$：在数据支撑点上 $$v^*\to-\mathbf{A}_t$$，也就是残差速度 $$\mathbb{E}[\epsilon]-\mathbf{A}_t=-\mathbf{A}_t$$。数据端的场不为零，但它被 $$1/(1-\tau)$$ 放大，数值上敏感——这解释了为什么实现里要把采样区间从 $$[0,1]$$ 收到 $$[0.001,0.999]$$。

把 $$\tau$$ 固定、沿 x 扫一遍，能看出这个场为什么不是直线。实验 A 在三个时间点上取了 $$x=-1.0,\,0.0,\,1.5$$ 三个位置：

| τ | x=-1.0 | x=0.0 | x=1.5 |
| --- | --- | --- | --- |
| 0.2 | 1.1242 | -0.9475 | -1.0000 |
| 0.5 | 0.2982 | -0.4164 | 0.2034 |
| 0.8 | -1.0282 | -0.2822 | 0.9490 |

读数有三层。第一层，**场随 x 单调**：同一时刻，右边的点速度更大（更指向数据端），符合直觉。第二层，**斜率不恒定，而且随 τ 变**：τ=0.2 时从 -1 到 0 掉了 2.07、从 0 到 1.5 只掉了 0.05，两段斜率差了近 60 倍；τ=0.8 时两段斜率是 0.75 与 0.82，几乎是线性的。第三层，**低 τ 段的非线性最重**，因为那里两个峰在 x 轴上仍然分得开，边际场必须在两峰之间做切换；τ 一大，高斯噪声把两峰糊成一团，场就退化成“减掉均值”的线性函数。

Euler 的误差正比于场沿轨迹的变化率。τ=0.2 那行“两段斜率差 60 倍”的几何，就是“10 步之后误差还在按 1/n 走”的来源：轨迹从噪声端下来，必然要穿过这段最陡的区域，而没有哪一步能把它走平。

## 7. 推理：10 步 Euler 与 1 步塌缩

并行去噪在统计上学的是**联合分布**。50 个动作 token 共享一个双向掩码、在同一次前向里被同时预测，模型建模的是 $$p(\mathbf{A}_t\mid\mathbf{o}_t)$$ 这个整体，而不是 $$p(\mathbf{a}_t\mid\mathbf{o}_t)\,p(\mathbf{a}_{t+1}\mid\mathbf{o}_t,\mathbf{a}_t)\cdots$$ 的分解。这个区别在动作块上不是形式问题：自回归分解把“整段的风格”（快慢、轻重）摊进每一步的条件里，某一步风格判错，后面就沿着错的条件一路走；联合建模让风格成为一个被同时决定的量，整段要么都快要么都慢。

代价是“逐 token 可检查”消失了——没法在中途停下来只重采样后半段，只能整块接受或整块重来。第 06 篇会看到这个代价有多具体：RTC 之所以用 inpainting 而不是“重新生成剩余部分”，根子就在这里。

推理就是从 $$\tau=0$$ 积分到 $$\tau=1$$，初始值是高斯噪声，积分器是最朴素的显式 Euler：

$$
\mathbf{A}_t^{\tau+\delta}=\mathbf{A}_t^{\tau}+\delta\,v_\theta(\mathbf{A}_t^{\tau},\mathbf{o}_t),\qquad \delta=0.1
$$

10 步。选 10 而不是 50 或 100，通常的解释是“够用了”。这句话对，但它掩盖了一个更有意思的事实：**一阶方法的误差严格按 1/n 走，10 步之后并没有平台期**。

合成探针上（用解析边际场做积分器，把“网络不完美”这个因素摘掉，只剩离散化误差），从 $$\tau=0$$ 到 $$\tau=1$$ 的 RMS 端点误差是：

| 步数 n | 1 | 2 | 3 | 5 | 10 | 20 | 50 | 100 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| RMS 误差 | 1.1322 | 0.4986 | 0.3369 | 0.2195 | 0.1170 | 0.0646 | 0.0278 | 0.0142 |

数据本身的标准差是 1.1338。所以 10 步的相对误差约一成，100 步才到 1.2%。1→10 步降 9.68 倍，10→50 步降 4.22 倍（理论 5 倍）——**10 步不是收敛点，是成本点**。π0 之所以能停在 10 步，是因为动作块的误差会被闭环重规划吸收：50 Hz 下每 1 秒就有一次新的推理，上一块的末段误差不会单独决定成败。

真正危险的是少步数下的**定性错误**，不是定量误差。1 步 Euler 有一个恒等式：

$$
\mathbf{A}^1=\epsilon-\big(\epsilon-\mathbb{E}[\mathbf{A}_t]\big)=\mathbb{E}[\mathbf{A}_t]
$$

第一步更新就用掉了整个 $$\tau$$ 区间，而 $$\tau=1$$ 的速度场与样本无关（上一节的端点结论），于是**所有初始噪声都被映射到同一个点**——数据均值。实验里 1 步终点的标准差是 $$9.94\times10^{-5}$$（只剩下积分下界残留的噪声），均值 0.2300，正好等于 $$\mathbb{E}[\mathbf{A}_t]$$。

这就把“1 步也能出动作”这件事的性质说清楚了：它出的是一个**常量动作**，与观测无关（除了通过 $$\mathbf{o}_t$$ 影响均值）。在双峰分布上，这个常量落在两峰之间，按最近中心归类会被判给多数模式——实验里 1 步的**归属错误率 36.92%**，约等于少数模式的全部质量。10 步降到 1.33%，100 步降到 0.08%。

分布层面同样单调：

| 步数 n | 1 | 2 | 3 | 5 | 10 | 50 |
| --- | --- | --- | --- | --- | --- | --- |
| 与真实分布的 W1 | 1.0193 | 0.4445 | 0.2770 | 0.1765 | 0.0905 | 0.0173 |

所以“步数”这个超参在 π0 里的作用不是“精度旋钮”，而是“能不能表达多模态”的开关：步数太少，多模态被平均掉；步数够多，才轮到误差幅度的问题。

机制值得单独说清楚，因为它是流匹配作为**生成模型**的全部价值所在。同一个观测、同一个模型，喂不同的初始噪声 $$\epsilon$$，会得到不同的动作块——这不是随机性带来的瑕疵，是设计意图。分化的位置在 τ 小的一端：边际场在两峰之间是“平均”的（把两侧质量往中间拉），但一旦轨迹被初始噪声推过了分界，它就会被最近的峰接管，后面几步只会加深这个归属。实验里 1 步的归属错误率 36.92%，说明“平均”恰好发生在第一步——第一步就把所有噪声映射到同一个点，分化还没开始就被掐掉了；10 步降到 1.33%，说明后续步数足以让轨迹各自归位。

换句话说，**10 步的作用不只是减小误差，更是给初始噪声留出分化的时间**。这两件事在数值上是同一个现象（二阶/一阶误差随步数下降），在语义上完全不同：前者是“算得更准”，后者是“能表达多个答案”。把 10 步理解成精度旋钮，会得出“再降两步也行”的错误结论——而 1 步的结果（常量动作）说明这条曲线的左端不是“精度差一点”，是“根本不是一个策略”。

这条恒等式还证明了一件更有意思的事：**1 步流匹配严格等价于 L2 回归头**。因为 $$v^*(\mathbf{x},1)=\mathbf{x}-\mathbb{E}[\mathbf{A}_t\mid\mathbf{o}_t]$$，一步更新后 $$\mathbf{x}=\mathbb{E}[\mathbf{A}_t\mid\mathbf{o}_t]$$，正是平方损失下回归头收敛到的条件均值。所以“用回归头”不是另一种架构，它是流匹配在步数取 1 时的特例。

这一条把两件事统一了：为什么 π0 之前的 VLA 用回归头也能做简单任务——那些任务的动作分布近似单峰，均值就是答案；以及为什么它们在叠衣服这类任务上崩掉——多峰分布下均值是一个物理上无意义的动作，比如“两只手各伸一半”。同理，任何“少步数流匹配”的性能天花板，就是回归头的天花板，只是它用几步把这个均值慢慢解开了一点。

还有一对经常被混为一谈的超参：**块长 $$H$$ 和去噪步数**。$$H$$ 决定“一次决策覆盖多长时间”，影响的是反应性与训练样本的时序跨度；步数决定“这次决策算得多准”，影响的是模态表达与延迟。改 $$H$$ 不改变延迟结构（推理频率就是 $$1/H$$ 秒一次），改步数则直接乘在延迟上。π0 固定 $$H=50$$、步数 10，是两个互相独立的预算决定，不构成“参数搭配”。

为什么不换高阶积分器？这是个标准做法，Heun 或 RK2 每步调用两次网络，局部误差从 $$O(\delta^2)$$ 降到 $$O(\delta^3)$$，全局从 $$O(1/n)$$ 降到 $$O(1/n^2)$$。同样的预算下比一下：10 步 RK2 要用 20 次网络调用，误差约 $$C'/100$$；20 步 Euler 也是 20 次调用，误差约 $$C/20$$。RK2 明显赢。

但这条账在 π0 里不成立，原因有两个。一是**网络误差淹没了离散化误差**：真实训练出来的 $$v_\theta$$ 与 $$v^*$$ 的差距远大于 0.117 这个量级，换积分器省下的那点误差落在噪声里。二是**延迟比误差更贵**：每步两次前向意味着去噪延迟直接翻倍，而延迟会以块间停顿的形式变成任务时间（第 9 节），在 50 Hz 的场景里这笔代价比精度更硬。这两条是判断，不是论文结论——论文只写了“用 10 步”，没写为什么不是别的积分器。

## 8. 时间采样：方向陷阱与 Beta(1.5,1) 的代价

训练时 $$\tau$$ 从哪个分布采，直接决定网络把容量花在哪一段。π0 论文只说“用一个偏向更噪时刻的 β 分布”，具体参数在开源实现里：

```python
time = jax.random.beta(time_rng, 1.5, 1, batch_shape) * 0.999 + 0.001
x_t = time * noise + (1 - time) * actions
```

$$\mathrm{Beta}(1.5,1)$$ 的密度是 $$f(t)=1.5\sqrt{t}$$，随 t 单调上升。在 openpi 的约定里 t=1 是噪声端，所以这个分布**偏向噪声端**——和论文的措辞一致，只是符号相反。$$\mathbb{E}[t]=0.6$$（均匀是 0.5）。

偏置的代价可以精确算。如果训练目标是“让每个 τ 上的误差都差不多准”（即对 τ 均匀加权），那么按 $$f$$ 采样相当于对每个样本施加了 $$1/f$$ 的隐式降权。有效样本数是

$$
\frac{\mathrm{ESS}}{N}=\frac{\big(\int f\cdot\frac1f\big)^2}{\int f\cdot\frac1{f^2}}=\frac{1}{\int_0^1 1/f\,\mathrm{d}t}=0.7507
$$

换句话说，**偏向噪声端让等效样本数降到 75%，要拿到同样的均匀精度得多采 1.33 倍数据**。分区间看更直观：

| τ 区间 | [0, 0.2) | [0.2, 0.5) | [0.5, 0.8) | [0.8, 1.0] |
| --- | --- | --- | --- | --- |
| Beta 采样占比 | 0.0894 | 0.2641 | 0.3620 | 0.2845 |
| 均匀采样占比 | 0.2000 | 0.3000 | 0.3000 | 0.2000 |
| 比值 | 0.45 | 0.88 | 1.21 | 1.42 |

数据端（τ 小）的样本不到均匀采样的一半，噪声端的样本是 1.42 倍。这笔交易划算吗？在这类模型上通常划算，理由要说准：**低 τ 处网络可以抄输入**——$$\mathbf{A}_t^\tau$$ 已经几乎等于 $$\mathbf{A}_t$$，把输入原样投射出去就能把损失压得很低，梯度里没有多少“任务语义”的信息。高 τ 处输入几乎全是噪声，模型必须靠图像和指令去推断动作，那才是真正要学的映射。所以偏向噪声端不是“更难的样本更重要”这种泛泛之谈，是把训练预算从“抄输入”挪到“看语义”。

这和上一节观察到的“低 τ 场更陡”不冲突：陡不等于有信息。那里的陡是 $$\mathbf{A}_t^\tau\approx\mathbf{A}_t$$ 造成的几何效应——x 稍微一动，条件期望就跟着动——而不是语义可分性。把这两件事混起来，会得出“应该多采数据端”的反向结论。

`*0.999 + 0.001` 这个缩放也值得记。它把采样区间从 $$[0,1]$$ 收到 $$[0.001, 0.999]$$，避开两个端点：τ=1 处 $$v^*=x-\mathbb{E}[\mathbf{A}_t]$$ 与样本无关，梯度信息量低；τ=0 处速度被 $$1/(1-\tau)$$ 放大，数值不稳。两行代码，各挡一个坑。

选 β 而不是别的分布，本身是个设计分歧。同一时期的图像扩散模型（SD3 那一系）用的是 **logit-normal** 采样，理由是它能把采样密度集中在中间的一段信噪比上——那里对图像语义最重要。π0 用 β 偏向噪声端，理由是机器人动作的“语义”不在中间：动作块的模式选择（往左还是往右抓）由**高噪声端的低频结构**决定，峰内的细节才靠低噪声端。这个差别不是口味问题，是两个任务的信号结构不同——图像要“看起来像”，动作要“做对了”，后者对模式选择更敏感。这条对照属于判断，π0 论文没有直接展开，但 β 的偏向方向和“1 步塌缩”的失败模式是一致的。

## 9. 工程账：KV cache 与一秒 chunk 的时延

第 4 节说过 prefix 的表示不依赖动作。这条性质在推理时直接兑现成一次缓存复用：第一个去噪步之前，把 prefix 前向一次、把 K/V 存下来；之后十个去噪步只前向 action expert 的 51 个 token（1 个状态 + 50 个动作），attention 对着缓存里的 prefix K/V 做。openpi 的 `sample_actions` 就是这个结构。

数值上这两条路必须等价。实验 E 用小规模多头注意力验证：cache 复用与全序列前向的输出差值 **0.000e+00**（逐位相同，因为计算路径一致）。为了证明这个测试不是“测了个寂寞”，加了一个负对照——只把 prefix 的 V 顺序打乱，输出偏差 1.472。顺带一个该记住的性质：**K 和 V 同步置换是等变的**，attention 输出不变，所以负对照必须打破配对。

把复用折成 token·次（一个 token 过一层算一次）：

| 场景 | 每步全量重算 | cache 复用 | 比值 |
| --- | --- | --- | --- |
| 2 相机（prefix 542 token） | 5930 | 1103 | 5.38× |
| 3 相机（prefix 798 token） | 8490 | 1359 | 6.25× |

prefix 按每相机 256 个 patch（SigLIP，224/14=16，$$16^2$$）+ 约 30 个语言 token 估。这个倍数说明一件事：在 π0 这个尺寸上，**十个去噪步的总开销大约是“一次全序列前向”的 1.2 到 1.3 倍**，而不是 10 倍。所以“10 步”在算力上并不奢侈，奢侈的是那一次全序列前向本身。

把 1359 拆开看，能看出重复计算落在哪。prefix 的 798 个 token 只做一次前向，但它作为 K/V 要被十步各读一次，于是 attention 里对 prefix 的部分是每步 $$51\times798$$ 次点积；suffix 内部的 $$51\times51$$ 则是十步全算。**被缓存的是 K/V 的投影，不是 attention 本身**——每一步仍然要对全部 key 做一遍点积。

这条区分很要紧。如果有人把“KV cache 让十步推理接近一步”当成结论，在长 prefix 的场景下会严重低估延迟：投影那部分省掉了，$$O(n^2)$$ 的注意力项一点没省。prefix 越长，缓存带来的相对收益越小——这正是后来几篇里“把 prefix 做短”（π0.5 的两段式、π0.7 的子目标图像）的隐藏动机之一。

反过来看，如果没有 cache 会怎样：10 步就是 10 次全序列前向，token·次从 1103 涨到 5930（2 相机），差 5.38 倍。这个倍数会直接压在模型尺寸上——延迟预算固定时，没有 cache 就只能把主干缩小近 5 倍。所以“两套权重（prefix 与动作不共享）” + “三块掩码（prefix 不被动作回看）” + “流时间作为每个动作 token 的输入特征（而不是 AdaLN 的全局调制）”这一串设计不是三个独立的优化，它们共同保证同一件事：**prefix 的表示与动作无关，因此可以缓存**。三条里任一条不成立，十步推理的成本结构就变了。

但 token·次不等于延迟。一秒的动作块、20 ms 的控制周期，这两个数一摆，就能看出同步执行的死穴：如果一次完整推理要 300 ms，那么机器人执行完当前块后必须**停下来等**下一块——而训练数据里没有这种停顿，策略从没学过“停一秒再动”。π0 在实际部署里就是同步执行的，代价是块间停顿。这个坑留到第 06 篇 RTC：那里会用同一个 inpainting 框架，把“等待”变成“边跑边算”。

有个从图像生成借来、在 π0 里**刻意没有出现**的技巧：classifier-free guidance。CFG 需要一条“无条件”分支，靠对比“有条件/无条件”的分数差来放大条件的影响。VLA 里这个前提不成立——条件是观测，去掉观测就没有任务可言，不存在“无条件生成动作”这件事。图像生成用 CFG 强化的是“画面要像这段文本”，机器人里对应的问题是“动作要听指令”，而这件事由训练数据（指令与动作成对）和损失函数承担，不是采样时的一个强度旋钮能补的。03 篇会看到相反方向的努力：KI 是在**训练侧**保证指令信息不被动作专家的梯度冲掉，而不是在采样侧加引导。

## 10. 数据配方：预训练与后训练

网络和目标函数只决定“能学什么”，决定“学到什么”的是数据。π0 的训练混合物有两块：

| 来源 | 内容 |
| --- | --- |
| 自有数据 | 7 种机器人配置、68 个任务；单臂 UR5e、双臂 UR5e、Franka、双臂 Trossen、双臂 ARX、移动 Trossen、移动 Fibocom |
| Open X-Embodiment | 22 种机器人的公开数据 |

任务选择的标准不是“解决某个应用”，而是**覆盖灵巧度的不同侧面**：收拾餐桌、装信封、叠衣服、理线、组装纸箱、插电源插头、打包外卖盒、扔垃圾。这些任务共享一个性质——它们对“多阶段、可形变物体、多种可行策略”这三件事都有要求。

语言标注是两级：**任务名**（粗）+ **segment 标注**（细，通常约 2 秒的子轨迹）。这个设计后来在 π0.5 里被推到极致（变成显式的子任务预测），但在 π0 里它只是让模型学会“指令可以指到子步骤”。

这条标注是个伏笔。约 2 秒的子轨迹描述，让模型在预训练阶段就见过“一条长指令 + 若干短描述”的配对。当时它只是把语言条件变细；到 04 篇的 Hi Robot，这套数据直接变成高层策略的训练输入；到 05 篇的 π0.5，子任务从输入变成模型的输出。一个不起眼的数据工程决定，成了后面两篇的接口——这也是这条系列里反复出现的一类现象：**后来被当成“新能力”的东西，往往是前面某篇里一个不起眼的数据格式**。

训练分两个阶段，对应 LLM 的 pre-training / post-training：

- **预训练**：在上述混合数据上训一个“什么都会一点”的基座。这个基座能跟指令、能做 rudimentary 的任务，但都不精。
- **后训练**：用高质量、窄分布的数据把某个任务做“好”。论文区分了两种后训练——数据量小的“高效后训练”（对应新任务的快速适配）与数据量大的“高质量后训练”（对应叠衣服、移动操作这类复杂任务）。

这个两段式结构解释了一个常被误读的现象：π0 在论文里的评测分数（bussing easy 0.971、shirt folding 1.000、grocery bagging 0.786、toast 0.750）**全部来自后训练的模型**，不是零样本基座。零样本能力只在“同分布任务”上被报告过。把后训练分数当成“一个通用模型直接能干活”的证据，是这类论文最常被引用错的地方。

另一个容易被忽略的点：跨本体的关键不在输出层拼接，而在**归一化**。每个动作维度按训练集 1%/99% 分位映射到 $$[-1,1]$$，这一手同时解决了两件事——不同机器人的量纲被抹平，离群动作不会把某一维的尺度拉爆。用分位数而不是最大最小值，是为了对长尾鲁棒；这在几十种机器人混训的数据里不是可选项。

最后是一个读数字的提醒。这些分数用的是评分 rubric：完全成功记 1.0，部分完成按比例给分（搬走一半物品记 0.5）。所以 0.971 的意思是“平均完成度 97.1%”，**不是“97.1% 的回合完全成功”**。部分分会把“做了一半卡住”稀释成 0.5，把完全失败藏进平均值里。读这类表格要专门去找 0 分的比例——那才是“这个策略根本不会做这件事”的证据。同一份表里 π0-small 与 Octo 大量为 0，就是这个意思：不是“做得差一点”，是“完全不会”。

还有一个容易被当成花絮的能力，其实是这套配方的直接推论：博客里提到机器人能在人从各个方向干预时恢复。这不是一个独立模块。流匹配学的是整个动作分布的场，训练数据足够多样时，“被推歪之后的样子”也在分布里，于是 $$\mathbf{A}_t^\tau$$ 落到偏离示范流形的区域时，边际场仍然有定义、仍然指向某个合理的动作。回归头的表现会完全不同——它只会输出“最像示范的那个动作”，没有“从偏离状态回到任务”这个概念，被推歪之后要么硬拉回原轨迹，要么输出一个折中值。

## 11. 这套配方在哪里失效

把 π0 的贡献拆干净之后，它的边界也就清楚了。以下五条都不是“实现不够好”，是这套设定的结构性限制：

**证据缺口：多模态建模的收益没有被单独测过。** π0 的对照是“整套系统”层面的——π0 vs 双向共享权重 vs π0-small vs OpenVLA vs Octo，没有“同一主干、同一数据，流匹配头 vs 回归头”这一格。这一格缺席，意味着“多模态建模到底贡献了多少”在论文里推不出来。合理的猜测是收益集中在**示范本身多模态的任务**上（同一局面人类示范过两种做法，比如从左边或右边抓），而在单峰示范的任务上，流匹配的作用退化成“更好的优化景观”——它把 L2 回归的均值化解掉了，但那些任务里均值化本来也不会发生。这是判断，不是论文结论。

**精度受一阶积分器限制。** 10 步的相对误差约一成，靠闭环重规划吸收。若任务要求亚毫米级的末端对齐（插螺丝、插网线），开环误差会直接决定成败——这类任务后来由 08 篇的 RLT 用在线 RL 补，而不是靠加去噪步数。

**语言跟随会衰减。** 加 action expert 意味着给预训练主干接上一组随机初始化的权重，它的梯度会改写主干表示。π0 论文自己报告了失败案例：指令是“把勺子放进餐具盒”，模型抓了垃圾。这不是流匹配的错，是“嫁接运动皮层”的代价——03 篇 KI 用梯度截断正面处理它。

**长程任务没有分解机制。** π0 只有一个层级：给定指令直接出动作块。十分钟的收拾厨房需要“先做什么、现在做到哪”，这是 04 篇 Hi Robot 和 05 篇 π0.5 的题目。

**它不从经验里学。** 全部训练信号来自人类示范。示范之外的行为（失败后怎么恢复、怎么把成功率从 80% 推到 95%）没有梯度来源——07 篇 RECAP 与 08 篇 RLT 分别从“大规模离线 + 在线”和“小规模在线”两个方向切进去。

| 限制 | 现象 | 根因 | 后续 |
| --- | --- | --- | --- |
| 开环精度 | 亚毫米对齐任务失败率高于示范水平 | 10 步一阶积分器，相对误差约一成 | 08 RLT（在线 RL 补精度） |
| 语言跟随 | 指令与抓取对象不符 | action expert 梯度改写主干表示 | 03 KI（梯度截断） |
| 长程分解 | 十分钟任务中途迷失 | 无层级、无记忆 | 04 Hi Robot / 05 π0.5 / 09 MEM |
| 无法自提升 | 成功率卡在示范水平 | 训练信号只有示范 | 07 RECAP / 08 RLT |
| 块间停顿 | 执行完一块要等下一块 | 同步执行，无异步机制 | 06 RTC |

## 12. 把公式对回代码

公式和代码之间最容易出错的是时间方向。下面这张表按 openpi 的变量名逐项对齐，看代码时可以直接查：

| 本篇公式 | openpi 变量 | 说明 |
| --- | --- | --- |
| $$\mathbf{A}_t$$ | `actions` | 形状 (b, H, d) |
| $$\mathbf{A}_t^\tau$$ | `x_t` | **方向相反**：openpi 的 t=1 是噪声 |
| $$\tau$$ | `time` | `Beta(1.5,1)*0.999+0.001` |
| $$\epsilon$$ | `noise` | 标准高斯 |
| $$\mathbf{u}=\epsilon-\mathbf{A}_t$$ | `u_t = noise - actions` | 与论文同号 |
| $$v_\theta$$ | `v_t` | 只取后缀最后 H 个 token |
| $$L^\tau$$ | JAX `mean(square(v_t-u_t), axis=-1)`；torch `mse_loss(..., reduction="none")` 后由训练脚本 `.mean()` | 对动作维求平均，见 §5 |
| 10 步 Euler | `dt=-1/num_steps`，`while time >= -dt/2` | 从 1 积到 0 |

训练步就四件事，采样步就三件事：

```python
# 训练：一次前向，一条 loss
noise = randn_like(actions)
time  = beta(1.5, 1.0) * 0.999 + 0.001
x_t   = time * noise + (1 - time) * actions     # 注意：t=1 是噪声
v_t   = model(prefix=obs, suffix=[state, x_t], time=time)
loss  = mean((v_t - (noise - actions)) ** 2, axis=-1)

# 采样：一次 prefix 前向 + 10 次后缀前向
_, kv = model(prefix_only=obs)                   # K/V 缓存
x, t = randn(H, d), 1.0
while t >= 0.05:
    x = x - 0.1 * model(suffix=[state, x], time=t, kv=kv)
    t -= 0.1
return x
```

两段代码之间只有一个数在变：`time` 从 1 走到 0。所有关于“10 步够不够”的讨论，本质上都是在问这个循环要跑几圈。

第一次读这份实现时，有三个地方容易卡住，都是“看起来无关紧要、实际上决定对不对”的细节：

1. **循环条件 `time >= -dt/2` 不是“多跑一步”**。`dt=-0.1`、从 `time=1.0` 出发，条件写成 `>= 0.05` 而不是 `>= 0`，是为了让 0.0999… 这种浮点残差也能通过最后一次判断。跑完 t 序列是 1.0 → 0.9 → … → 0.1 → 0.0，正好 10 步。
2. **`suffix_out[:, -action_horizon:]` 那个切片不能省**。π0 的 suffix 是“1 个状态 token + H 个动作 token”，不切就多出一行，形状对不上动作维度。到了 π0.5 模式这行切片仍然在，但已经切不到东西——那时状态被离散成文本进了 prefix，suffix 只剩 H 个动作 token。
3. **损失是 `mean(..., axis=-1)` 而不是 `sum`**。这一条在第 5 节说过，但它在代码里只是一行、很容易被当成风格问题改掉，改完混训的权重就悄悄变了，而且 loss 曲线看不出异常。

三个都属于“抄代码抄不错、但改代码会改错”的类型。后面几篇会继续遇到同类的东西——KI 的 `sg` 作用在哪张矩阵上、RTC 的 mask 是实数而不是布尔，都是这种一眼看不出分量的细节。

最后补一句两套实现的对照。上面所有行号引的是 JAX 版（`src/openpi/models/pi0.py`），PyTorch 移植版（`src/openpi/models_pytorch/pi0_pytorch.py`）逐项对得上，只是文件组织不同：

| 环节 | JAX | PyTorch |
| --- | --- | --- |
| 三块掩码 | `pi0.py` L19-L44 | `make_att_2d_masks` L52-L81，同一个 cumsum 技巧 |
| 后缀嵌入与时间注入 | L150-L186 | `embed_suffix` L238-L315 |
| 训练前向 | L189-L215 | `forward` L317-L374 |
| 十步采样 | L217-L279 | `sample_actions` L377-L420 + `denoise_step` L422 起 |

真正不同的只有两处，都是框架机制而非算法：JAX 用 `jax.lax.while_loop` 把整个去噪循环编进计算图，PyTorch 用 Python `while` 配 `use_cache=True`；损失归约位置见 §5 那张表。至于 π0.5 的 adaRMS 分支，两套实现都有——`Pi0Config(pi05=True)` 一开，`embed_suffix` 走另一条路，而且做的第一件事是**不再插入单独的状态 token**（状态被离散成文本塞进 prefix）。这个分叉是第 05 篇的入口。

下一篇拆 FAST：同样是解决“动作怎么表示”，它走的是完全相反的方向——不学连续分布，而是先用 DCT 把动作块压成 30 到 60 个 token，再让自回归模型去预测。两条路的取舍不在精度，在**训练速度与推理延迟怎么分配**。
