### Gym-Anything：把造仿真当成 coding agent 任务，25 个仿真上前沿模型平均奖励 0.06

`值得读 ★★★★☆ ｜ 影响力 ★★★☆☆`

**来源**：[arXiv:2610.40565](https://arxiv.org/abs/2610.40565)

真实、快速的机器人仿真能让具身模型大规模训练并迁移到现实，但几十年过去，可用的仿真仍只覆盖很窄的真实任务与物理现象。瓶颈在于造更好的仿真需要大量专家投入，因而不具备规模性。这篇的核心判断是：**造仿真本身就是 coding agent 任务**，所以 coding agent 的进步会直接转化为更丰富、更忠实的仿真。

具体做法是：按美国 GDP 数据挑选仿真以覆盖有经济价值的物理工作，定义「什么算好仿真、什么算好任务」，并用一个对抗式的创建–审计循环逐条检查。用这条流水线构建了 RoboWorld——25 个仿真、25 个测试与 175 个训练 RL 环境，难度各异。

最值得注意的是结果：**即使最好的前沿模型在每个 RoboWorld 测试任务上都失败，平均奖励只有 0.06**。这个数字把当前能力天花板量化了。论文在 RoboWorld 之上给出了几条让前沿模型改进的路径：跨多次尝试的上下文学习、读取仿真器状态的特权教师、以及自我改进机制等。

### ELEVATE：任务反复失败时，让 coding agent 自己写 RL 问题补上控制器

`值得读 ★★★★☆ ｜ 影响力 ★★★☆☆`

**来源**：[arXiv:2610.38388](https://arxiv.org/abs/2610.38388)

四足机械臂能靠全身交互扩展工作空间，但任务规划 agent 的能力受限于它手上有哪些控制器。ELEVATE 的做法是**从任务程序精化过程中的持续性失败里识别缺失的全身控制能力**：当失败指向某种缺失的物理能力时，由一个 coding agent 提出并迭代精化一个强化学习问题——指定行为特定的奖励、课程与终止条件；验证通过的控制器进入能力库，并与已有控制器组合后重试任务。

从一个预训练的 loco-manipulation 控制器出发，ELEVATE 在 7 个仿真任务的序列上自主获得了靠墙抬升、支撑式操作与下墙三类控制器。在超出初始控制器工作空间的 5 个任务上，五次独立运行的平均成功率为 98.4%–100%，而使用固定控制器库的 coding agent 基线无法完成这些任务。合成出的任务程序连同获得的控制器**无需真机训练或微调**就迁移到了实体四足机械臂：rack 取物 18/20，地面到货架放置 16/20。

### LOGIV：动作用完了不算完，条件还得继续成立

`值得读 ★★★☆☆ ｜ 影响力 ★★☆☆☆`

**来源**：[arXiv:2610.40016](https://arxiv.org/abs/2610.40016)

agentic 机器人要把高层目标转成动作，同时保证后续步骤所依赖的物理条件持续成立。一个动作做完了，不等于它的效果会保持——后续的扰动可能让剩余计划仍在假设的支撑失效。

LOGIV 是一个任务图工程框架：把验证过的计划编译成「条件–支撑」边与「资源–顺序」边，在执行中检查其物理有效性，失败后用依赖追踪确定必须恢复什么；修复受未完成的动作约束，合并后的续接方案在执行前再做一次符号验证。框架运行在现有 VLA 与世界动作模型之上。

<h2 id="cat-world-model">世界模型</h2>

### Context Compaction：把「重访不一致」当成上下文检索问题

`值得读 ★★★☆☆ ｜ 影响力 ★★★☆☆`

**来源**：[arXiv:2610.38980](https://arxiv.org/abs/2610.38980)

观察者重访某个区域时，现有世界模型常常无法一致地重新生成它。这篇把它明确界定为**上下文检索问题**：LLM agent 在两个层次管理上下文检索——模型层由 KV cache 设计决定多少上下文能装进内存，agent harness 层由 harness 决定送进 LLM 的上下文。而已有的世界模型工作几乎只关注模型层。

三项贡献：① 一个测量世界模型上下文检索的 benchmark，每个 episode 生成新世界以避免模型靠训练数据回忆房间，并把上下文检索与「依据邻近帧猜测」区分开；② 一个为世界模型做上下文压缩的 agent harness（作者称此前无人研究）；③ 用该 benchmark 比较四种世界模型设计。结果是上下文压缩让世界模型**无需重训就能检索到超出其上下文窗口 4 倍远的房间**；但带滑动窗口注意力的世界模型在「做梦」（dreaming）时会丢掉大部分上下文检索能力——因此对 dreaming world agent 而言，用上下文压缩扩展世界模型的reach，比换成滑动窗口更划算。

<h2 id="cat-rl">强化学习</h2>

### 在线稠密 RL 训 UI 导航：8B 模型 OOD 泛化提升近 7 倍

`值得读 ★★★☆☆ ｜ 影响力 ★★★☆☆`

**来源**：[HuggingFace Daily Papers](https://huggingface.co/papers/2610.39264) ｜ 论文：[arXiv:2610.39264](https://arxiv.org/abs/2610.39264)

前沿视觉语言模型做 UI 导航能力强但推理成本高，无法日常使用；而小模型走 SFT 或离线 RL 又常把静态轨迹背下来，执行脆弱且无法从错误中恢复。这篇提出在**真实 iOS 应用上直接做在线强化学习**的框架，把 agent 拆成规划 agent 与 UI grounding 模型两个专门部件，用 LLM-as-a-Judge 提供奖励信号：稠密的 step 级反馈评估中间进展，外加一个终止奖励评估整体完成度。为用好这种双重奖励结构，优化用 PPO 配合 step 级优势估计，并提出 **GiGPPO**——一种邻居条件化的价值估计方法，利用并发轨迹中视觉相似状态的奖励信号来稳定 critic。基础设施侧编排数百个并发虚拟 iOS 设备。

在 UINavBench、iOSWorld、AndroidWorld 上，在线 RL 训练的 agent 明显超过 SFT 与仅用终止奖励的 RL 基线，并加快训练收敛。8B 的 RL agent 在向 Android 环境的分布外泛化上比 SFT 基线提升近 7 倍，在真实 iOS 应用上超过 Gemini-3.5-Flash、与 Gemini-3.1-Pro 持平。
