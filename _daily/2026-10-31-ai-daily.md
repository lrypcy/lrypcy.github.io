<h2 id="cat-embodied">具身智能</h2>

### 让规划器同时选技能、选物体、给几何目标：四足局部操作端到端推取 93.3%

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.40248](https://arxiv.org/abs/2610.40248)

导航类工作几乎都假设「存在一条无碰撞路径」，但在有可移动障碍的杂乱环境里，到达目标可能必须先发生物理交互。经典做法用几何规则与任务特定逻辑编码这些行为，学习类方法又常把决策空间压成低维运动指令或预定义动作集。这篇把决策空间放宽到**联合选择技能、相关物体与几何目标**：一个用合成数据做 LoRA 微调的语言条件任务规划器，把自然语言任务与结构化场景表示映射成长短不一的参数化动作序列，再交给低层强化学习策略执行。

论文报告规划器学到了交互式导航背后的几何关系，在交互导航任务上优于经典规划器与被提示的前沿模型。一个反直觉的对照是：与从零训练的模型比较表明，**表示足够结构化时，组合能力并不需要预训练**；预训练换来的是更可靠的几何目标。低层是一条端到端全身平面推取策略：仿真成功率 93.3%，分层基线为 83.5%，完成时间缩短超过 60%；真机上分层结构给出正确的技能组合 44/45 次，端到端成功 34/45 次。

### RoboSeed：拒绝给出总排名的评测框架，因为证据本身不够格

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.40026](https://arxiv.org/abs/2610.40026)

选一个机器人动作模型，需要知道任务能力、适配成本、部署要求，还需要知道**报告结论本身有多可靠**——只看成功率对不同算力预算的人帮助有限。RoboSeed 是一套面向 VLA 与世界动作模型的多维评测框架。它的方法论立场值得单独记：先判定「什么时候比较才成立」，缺的测量保持显式空缺，**不完整的聚合分数直接不给**，再用加权输入覆盖度指出证据缺口在哪。

在代表性模型上的结果给出三类差异：随预算不同的骨干选择、对适配配方（adaptation recipe）的敏感性、语言接口与视觉接口之间的差距。作者明确写出边界——不完整的服务侧轨迹与异构实验协议**使得不到总体数值排名**，本研究提供的是维度级评估与后续测量的优先级。这套克制与昨天「不完整就不发分」的处理是同一类判断。

<h2 id="cat-world-model">世界模型</h2>

### 视频生成与世界模型在「agent harness」上相遇：一份把三条路线摆开的报告

`值得读 ★★★☆☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.40191](https://arxiv.org/abs/2610.40191)

两份趋势正在同一个位置交叉：视频生成从端到端合成转向**智能体化生成**（靠规划、工具使用与反馈得到连贯可控的多镜头视频）；视频世界模型则提供动作条件观测与预测未来，充当智能体的交互环境。报告的切入点是 **agent harness**——围绕视频模型的可执行运行时：构造上下文、暴露工具、维护状态、路由反馈、管理预算。

它沿三个方向展开：其一，智能体化视频生成，harness 协调脚本、镜头规划、素材管理、拍摄与剪辑，以及随之而来的评测难题；其二，智能体化世界建模，harness 中介观测、控制、执行与状态，其中混合设计让**游戏引擎或智能体自己写的程序维护世界状态、视频模型只负责渲染观测**，并讨论两者如何互相评测与互相改进；其三，视频模型研发中的递归自我改进，区分输出层修改与更深层的更新。这是一份定位与路线图式的报告，不提供可摘录的实验数字，价值在把两条路线的公共部件命名出来。

### GROME：把记忆拆成「静态几何 + 动态实体」两本账，免训练插回世界模型

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.39812](https://arxiv.org/abs/2610.39812)

视频世界模型的长程一致性，难在观测内容掉出上下文窗口之后。现有记忆机制要么把历史当作隐式上下文检索——仍受上下文容量限制，且把静态与动态信息缠在一起——要么把历史压成显式的全局表示，难以刻画不断演化的动力学。GROME 的做法是先分解：把「场景里不变的几何」和「正在动的实体状态」当成两类对象分别维护。

检索阶段据此挑**空间上对齐的静态历史**来消除几何漂移，同时带上最新的动态实体状态以保证时间连续；注入阶段是免训练的——顺着视频世界模型原生的条件通路把分解后的记忆塞回去，因此冻结骨干的画质与可控性都保留，不需要额外训练。作者还指出一点工程价值：除了自回放（self-rollout），GROME 可以直接把外部观测当作即插即用的记忆接入，从而支持可控的视频续写与场景探索。

<h2 id="cat-rl">强化学习与后训练</h2>

### 先按教师做校准蒸馏，再省掉合并开销：动态路由 MoE 后训练拿到 85.92

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.39876](https://arxiv.org/abs/2610.39876)

动态路由 MoE 的后训练有个组合难题：把各自独立优化好的专家整合进来时，怎么让合并（consolidation）这步不贵。这篇把两件事放在一起做。训练侧是**校准多教师在线策略蒸馏 C-MOPD**：在每个被选中教师的局部 Top-K 支撑上做匹配，配教师间损失归一化与裁剪。执行侧走「容量平衡路由之后」的路径，让整合与推理共用一套布置。

论文报告：在四个启用推理的数学与代码基准上，未加权平均 **85.92**，对照 Qwen3-8B 的 80.33 与纯 SFT 的 74.21，并在 12 项更宽评测里的 10 项优于 SFT；在 PPU 上的 profile 显示，合并后的执行配置把整合步时间从 398.7 秒降到 139.3 秒，即相对串行执行观察到 **2.86 倍**加速。作者同时限定了解读口径：这反映的是整套训练与执行框架的效果，不是任何一个单独组件的功劳。

<h2 id="cat-agents">智能体与超级智能</h2>

### CORAL：长程智能体不是被能力卡住，是被自己的工作记忆淹掉——让它可以「带着结论重开一局」

`值得读 ★★★★★` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.40350](https://arxiv.org/abs/2610.40350)

LLM 智能体在长程任务上常见失守点被诊断为**认知超载**：工作记忆被不断膨胀且无关的信息塞满，注意力被稀释，规划与推理随之失效。CORAL（认知资源自我分配）的思路是让智能体主动优化自己的上下文：它实现成一套可被智能体调用的工作记忆管理工具，允许智能体给任务进度和**已验证事实**打检查点，再自适应地开启新的一轮求解——把杂乱的上下文重置，只保留检查点内容，从干净状态继续推理。检查能力本身用 Multi-episode Agentic Reinforced Policy Optimization 训练。

结果有两层意义。能力上，8B 模型在 GAIA 上拿到 42.8% 平均准确率，且在最难的高程任务（Level 2、Level 3）上增益尤其明显。成本上，**它比 ReAct 智能体少用 6–7 倍输入 token**——省 token 不是附带好处，而正是「丢掉无关历史」这个动作的直接结果。方法还能迁移：在多跳知识问答与更难的 BrowseComp 上，把一个很强的专有智能体提高了 8.0 分。

<h2 id="cat-infra">AI Infra</h2>

### 浏览器里的投机解码要整轮留在 GPU：比 WebLLM 快 3.5–8.6 倍，峰值 10.2 倍

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.39761](https://arxiv.org/abs/2610.39761)

WebGPU 让网页内做私有离线推理成为可能，但浏览器特有的开销——算子分发、进程间通信、同步回读、单 token kernel——既拖慢解码，也让常规投机解码不划算。这篇给出一个 WebGPU 运行时：确定性的小批量整数 kernel 加速多 token 验证，同时在同一套量化运行时里与贪心解码**严格一致**；一个 GPU 常驻循环把起草、验证、接受与 KV 缓存维护全留在设备上，取消每 token 一次的 CPU 决策；起草侧干脆不用 draft 模型，而是复用页面内容、对话历史与会话记忆做上下文混合，再由一个感知设备的控制器按实测成本调节投机宽度与提交窗口。

在 0.5B–8B 的七个模型、11 个任务、三种客户端 GPU 上：笔记本 GPU 解码比 WebLLM 快 **3.5–5.4 倍**，核显 4.8–6.2 倍，工作站 4.8–8.6 倍；仅 GPU 常驻循环加投机这两项，相对已优化的 kernel 再贡献 1.8–3.2 倍。输出与该运行时的量化贪心**逐字相同**，GSM8K 平均分与 WebLLM 持平；可选 draft head 把峰值抬到 10.2 倍，会话记忆则在不额外下载权重的前提下再涨一点。

### Rimuru：把权重与注意力状态放进同一个页池，吞吐最高 19.03 倍、TTFT 平均降 98.1%

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.40305](https://arxiv.org/abs/2610.40305)

现有系统分别为模型权重与注意力状态预留显存，中间是一道**固定边界**：负载重时状态容量不足，压低了并发与吞吐；负载轻时一侧的空闲内存又挪不给另一侧。现代 LLM 还带来布局与生命周期各异的异构张量，让共享池本身不够用——不同张量的分配粒度和执行布局并不通用。

Rimuru 用弹性专家卸载把显存管理真正统一起来：建一个共享页池实现跨异构张量的弹性复用；用**内存视图**让每类张量按自己的页大小与页表解释同一块空间；用大页对齐加上可分裂/合并的多级页分配器实现跨类型容量复用；配一个页表感知的融合 MoE kernel，直接读取非连续的专家权重而省掉拷贝；最后由工作负载感知的调节器按运行时需求在各类张量之间重新分配页。系统实现在 vLLM 之上，与现代 LLM 兼容，评测里**吞吐最高达基线 19.03 倍，TTFT 平均降低 98.1%**。

### 投机解码的能耗账：省下的那部分会被大 batch 吃掉，甚至转成亏损

`值得读 ★★★★★` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.40287](https://arxiv.org/abs/2610.40287)

数据中心被设施功率卡住，于是「每 token 能耗」决定能服务多少 token，而延迟目标又限制每个用户多快拿到结果。解码时每个 token 都要把全部权重从显存读一遍：批处理能摊薄这次读，但不会让任何单个用户更快；投机解码可以——一次前向验证多个草案 token，复用同一次权重读。而**每个草案 token 无论是否被接受都要验证**，所以省多少电只取决于接受了几个。

在生产服务条件下（SGLang、开启 CUDA graph、H100 与 H200、batch 至 64、5 个语料）测下来：dense 模型上是**验证而非起草主导能耗**；batch 越大，节省越小，因为批处理已经把那次权重读摊掉了。大 batch 下块式起草器会把验证推过算术与访存的平衡点、进入算力受限区，**此时节省变成亏损**；接受率低的起草器直接抬高每 token 能耗。要用投机满足更严的延迟目标，还得再贴一笔电。接受率本身也随内容变：所有被评的起草器在对话上比在代码上接受得更少，训练出来的起草器在低资源语言罗曼什语上比在英语上接受得更少。作者的结论是：批处理已经吃掉了投机的能量来源，留给「保延迟的 DVFS」几乎没有余量。

### 扩散语言模型的 KV 缓存在被量化之前就已经不一致了

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.39853](https://arxiv.org/abs/2610.39853)

自回归模型的 KV 缓存量化之所以是「缓存重建」问题，前提是因果注意力下被缓存的前缀状态精确不变。扩散语言模型把这个前提拆掉了：快推理会在去噪步之间复用 KV 状态，但**双向表示会随着掩码 token 被逐个揭开而变化**，于是复用到的缓存本身就可能已经过期。

作者的处理方式很有方法意味：先按输出层与注意力层两类行为指标把不一致诊断出来，再决定量化怎么施加，而不是直接套用低比特值量化。评测在 LLaDA 与 Dream 上跑 GSM8K、HumanEval、MATH、MBPP：在所报告的 4-bit 与 2-bit 前缀/双缓存设置中，dLLM-KVQ 取得量化方法里最高的平均分。

<h2 id="cat-safety">安全与对齐</h2>

### 弱而不对齐的智能体群，可以把对齐的前沿模型当成不知情的外包工

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[LessWrong](https://www.lesswrong.com/posts/r7y3MnouZ5bAwbiss/unaligned-weak-models-might-exploit-powerful-aligned-models)（系列第三篇）

此前讨论的多是强模型把活儿委派给弱而不对齐的模型时失控；这篇讲反向：一群弱的、不对齐的智能体把**强对齐模型当承包商**用，且始终不告诉它这份工作是为了什么。作者的类比很直白——世上多的是「邪恶而愚蠢的人领导着正直而聪明的人」，智能体群同样可以，只要确保被调用的对齐模型永远不知道自己的工作会造成什么。

作者强调这在小规模上已被测量：Jones、Dragan 与 Steinhardt 证明把两个各自安全的模型组合起来，完成有害任务的频率远高于任一模型单独行动——前沿模型只拿到看起来无害的片段，弱开源模型做剩下的部分。例如要拿到有漏洞的代码，前沿模型写安全实现、弱模型再植入漏洞：**Claude 3 Opus + Llama 2 70B 成功率 43%，而两个模型单独都不超过约 3%**。那项实验里任务切分由人决定，但作者也提到他们让弱模型自行切分。这是作者的论证与既有测量的综述，不是新实验结论。

### TextSeal2：水印要能在投机解码下活下来，被拒草案换掉也不掉信号

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.40613](https://arxiv.org/abs/2610.40613)

无损水印的难点是既不改输出分布又留得住信号。TextSeal2 额外要顶住**投机解码**：草案被拒后替换上来的 token 仍然带着同一套密钥的水印，且接受率不受影响；它同时保住输出多样性，且不增加可测的推理延迟。机制上，前代 TextSeal 用路由把 token 分到多个候选以恢复多样性，而这里让竞逐的胜出者按无记忆性复现块验证，从而保证输出严格服从目标模型。

在三个 LLM 上评测：同等输出多样性下，误报率 10⁻³ 时，检测 100 token 回答的召回比 TextSeal 高 **8–22 个百分点**，与 textGrain 相当但不需要 logits 之后的优化。开了投机解码后差距更明显——同一接受率下，检测 200 token 回答分别比 TextSeal 与 textGrain 高 **18 与 22 个百分点**。
