<h2 id="cat-embodied">具身智能</h2>

### PDRVLA：不在线生成视频，也能有物理动力学——LIBERO 99.3%、RoboTwin 2.0 93.6%

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.37381](https://arxiv.org/abs/2610.37381)（[HF Papers](https://huggingface.co/papers/2610.37381) ⭐148）

VLA 模型的短板是物理动力学理解不够；视频世界模型能补上场景动力学，但生成未来视频会把高延迟塞进控制回路。PDRVLA 的折中是一个**轻量物理动力学模块**：从视觉-语言特征里抽出物理 token 来条件化动作生成，**推理时不做任何在线视频生成**。模块通过直接预测未来的 RGB、深度与光流特征来学习，并用一个冻结的预训练视频世界模型提供辅助监督。训练数据完全来自公开数据，再靠人到人机合成、子任务标注与具身思维链（ECoT）标注扩充。

四个仿真基准的成功率：LIBERO **99.3%**、LIBERO-Plus **89.9%**、RoboTwin 2.0 **93.6%**、SimplerEnv **81.5%**。消融显示世界模型监督确实改善了未来预测，并分别考察了子任务条件、未来物体位姿监督与 ECoT 训练对动作成功率的影响。

### VLA 还是 WAM？这是个把三件事捆在一起的问题，拆开后发现「只要动作模型」

`值得读 ★★★★★` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.37219](https://arxiv.org/abs/2610.37219)（[HF Papers](https://huggingface.co/papers/2610.37219) ⭐6）

VLA 与 WAM 两个阵营在争控制策略该继承视觉-语言模型的预训练知识，还是视觉生成器的。作者认为这场争论**把三个可分离的选择捆在了一起**：骨干初始化、施加在未来观测上的目标函数、以及那套未来损失机制在推理时是否保留——因此一个 VLA 与一个 WAM 之间的差距没法简单归因到其中任一项。

拆开后得到一个统一框架 JAM：预训练视觉骨干 + 动作专家，训练时同时用动作损失与「foresight 损失」。后者让当前观测的特征去预测**已录制未来的冻结编码**，预测头在训练后直接丢弃，于是训练与推理都不涉及视觉生成，骨干也可以自由选。结果很硬：与配对的 FastWAM 相比，成功率从 97.0% / 55.3% / 91.2% 提到 **98.2% / 64.5% / 91.4%**；因为 foresight 目标可以缓存，每样本每次更新的在线训练估算 FLOPs 相对 FastWAM **减少 73%**。作者的结论是：未来监督能在**不需要视觉生成、也不增加推理机器**的前提下改善控制。

<h2 id="cat-world-model">世界模型</h2>

### GAWM：不到 100M 参数的潜空间世界动作模型，多任务操作上学得比十亿级 WAM 好

`值得读 ★★★★☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.37091](https://arxiv.org/abs/2610.37091)

多数 WAM 建在十亿级的视觉-语言或视频生成骨干上，训练成本与推理延迟都很高。GAWM（Geometry-Aware World Model）走相反方向：在**冻结的 DINOv3 编码器潜空间**里预测未来观测。每个相机视角的特征先压缩成一小撮 token；一个轻量预测器以任务（而非动作）为条件，预测这些 token 在两个未来时刻的取值；监督信号是未来帧的稠密 patch 特征，从而要求它编码未来场景的空间布局；最后由一个动作解码器直接从当前与预测 token 回归出一段未来动作。

结果：参数量不到 100M、且**不做任何机器人或视频预训练**，GAWM 在 RoboTwin 2.0 上超过十亿参数的 WAM，在 LIBERO 上与十亿参数的 VLA 打平；在双臂真机上，它对留出示范的动作预测误差低于微调过的十亿参数 VLA，而推理延迟明显更低。

### Hy-Nomas：8B 扩散骨干做自由形式交互世界生成，权重与基准全部开源

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.36729](https://arxiv.org/abs/2610.36729)（[HF Papers](https://huggingface.co/papers/2610.36729) ⭐124） ｜ 代码：[Tencent-Hunyuan/Hy-Nomas](https://github.com/Tencent-Hunyuan/Hy-Nomas)

交互式世界生成要求模型连续服从多条指令，同时保住相关历史与动作后果。Hy-Nomas 是一个 8B 扩散骨干的视频世界模型，支持**自由形式文本指令 + 连续相机控制**跨多轮交互，按当前输入与缓存历史生成长度可变的片段。核心设计是把结构化视频描述与**动作感知的因果注意力**对齐：描述性上下文允许跨片段可见，而动作指令被限制在它该起作用的时间窗内。一个视觉-语言 Prompt Enhancer 把用户请求与多模态交互历史翻译成下一段的结构化条件；训练按多阶段课程推进——因果生成、文本交互、相机控制、在模型自产历史上训练——再做扩散蒸馏。

人工评测中它优于现有世界模型，并且模型权重、代码与基准连同轻量适配流程一起放出，可复现性是这条路线上少见的。

<h2 id="cat-rl">强化学习与后训练</h2>

### MPO：critic 值主要跨轮次变化，于是把优势估计和策略更新都锚在「轮」这个尺度

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.35013](https://arxiv.org/abs/2610.35013)（[HF Papers](https://huggingface.co/papers/2610.35013) ⭐380）

长程 LLM 智能体与环境交互时是**整轮整轮**地交互，但每个动作是逐 token 生成的。作者的观察是：critic 值的变化主要发生在轮与轮之间，而不是同一轮内部的 token 之间。既然信号在哪个尺度上变化，优化就该锚在哪个尺度上，他们提出 MPO（Multiscale Policy Optimization），由两部分组成——多尺度优势估计 MAE 把轮的粗粒度与 token 的细粒度信用分配结合，轮级重要性采样则让策略更新也对齐到轮尺度。

在搜索、工具使用与自动化任务上，用 4B 与 30B-A3B 模型做的大量实验里，论文报告它相对强 RL 基线有一致的增益（摘要未给出单项数字，具体表号见论文）。这条思路和「智能体的信用该分配到哪一级」是同一类问题，和昨天那篇孪生世界信用分配正好互补。

### 多目标 RL：用「目标冲突系数」量化失衡的代价，再用路由系综摊薄它

`值得读 ★★★☆☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.35733](https://arxiv.org/abs/2610.35733)

多目标 RL 的难点是学出能平衡相互竞争目标（有用性 vs 诚实性、速度 vs 能耗）的策略，而最优策略会随目标权重的组合剧烈变化，变化幅度取决于目标之间有多冲突——这让「每个偏好训一个策略」极其费样本。作者先引入**目标冲突系数**，并据此在线性设置推出近似最优的 regret 界，把「目标不对齐」对学习效率的损害量化出来。

算法侧有两条：路由系综策略学习维护一小组基策略，把轨迹动态路由到期望回报最高的那个；另一条把轨迹选择本身当作缓解冲突的手段，提出核代理轨迹归因，去估计一组轨迹的反馈如何影响其他轨迹的学习——核能捕捉轨迹之间的协同与拮抗这类非线性相互作用。实验里，路由系综在 Meta-World 与 MO-Gymnasium 的在线环境上把平均表现提高 **4.3%**；核代理归因与留一法分析的相关性比现有基线高 **50%**。

<h2 id="cat-agents">智能体与超级智能</h2>

### The Trinity：把任务树按「能力」而非表面类别重排，让环境生成与 harness 演化互相喂养

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.36077](https://arxiv.org/abs/2610.36077)（[HF Papers](https://huggingface.co/papers/2610.36077) ⭐386） ｜ 代码：[InfRec-Cardinal/The-Trinity](https://github.com/InfRec-Cardinal/The-Trinity)

多模态智能可以被看成「世界」与「智能体」在人引导下通过交互共同演化，但放大这套过程有两个瓶颈：构造异构、可验证的环境很贵；靠人工迭代 harness 跟不上任务多样性与复杂度的增长。作者的关键假设是：**模态与表面形态不同的任务，可能共享同一套底层能力要求**。

Trinity 因此用三个角色把世界生成与 harness 演化缝在一起：Evolver 依据被验证过的执行轨迹，把任务组织的依据从表面类别换成共享要求，将原任务树重排成一棵**能力树**；在同一节点上，Creator 把共同要求抽象成简化的、可验证的仿真世界用于能力学习，再用原始任务上的评测衡量迁移（作者称之为 Capability-Driven Real2Sim2Real）；Explorer 沿能力树逐级演化。⭐386 的今日热度说明这套「自动重排任务组织」的说法戳中了人。

<h2 id="cat-infra">AI Infra</h2>

### DeepInfer 的优化 SGLang 全有了：4 卡打平、64 卡 decode 单步最多缩短 7.4%

`值得读 ★★★★★` ｜ `影响力 ★★★★☆`

**来源**：[青稞社区](https://qingkeai.online/blog/sglang-deepinfer)（SGLang Team 署名） ｜ 原文：[lmsys.org 博客](https://www.lmsys.org/blog/2026-10-24-dsv41-deepinfer)

DeepSeek 开源了支撑自家服务的推理引擎 DeepInfer 及其整套 kernel，这套东西基本定义了 DeepSeek-V4.1-Flash 现在能跑多快。SGLang 团队直接在 DeepInfer 自己的基准、同一批硬件上对比：**4× GB300 与 4× B300 上 prefill 吞吐最高到 1.04 倍，64× GB300 上 decode 单步耗时最多缩短 7.4%，其余测试点差距在 1% 以内**。

集成面比结果更能说明问题：FlashMLA、DeepGEMM、DeepEP、DeepSelect 与 TileLang kernel，加上 Mega 系列（MegaAttention、MegaMoE、MegaGate、Mega-mHC）都已跑在 SGLang 主干上——MegaMoE 把 token 分发、专家 GEMM 与 combine 融进一个 kernel，MegaAttention 是 B300/GB300 上单机与 prefill/decode 两侧的默认注意力路径。并行用 DP attention + 专家并行，64 张 GB300 上 prefill 取 DEP4、decode 取 DEP64，大规模 EP 下再配 EPLB 平衡专家负载；此外还有 checkpoint 自带 DSpark draft 模型的投机解码、SWA bounded replay 与主机内存里的 Engram 表。作者还点明一句要紧的：API server、KV cache 系统、prefill/decode 分离与跨副本负载均衡这三样，正是 DeepInfer 的 README 写明「本次发布不包含」的部分。

### TAO：智能体服务要把「工具什么时候回来」当成调度变量，TTFT 最多降 36.3%

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.37230](https://arxiv.org/abs/2610.37230)（[HF Papers](https://huggingface.co/papers/2610.37230) ⭐16）

智能体服务在「集群 GPU 上的模型推理」与「分布式 CPU 上的外部工具」之间来回切换。现有系统有两个盲区：评测服务时忽略**工具结果的就绪时刻**，白白浪费有限资源；GPU 上的准入与放置靠启发式规则，决策次优。TAO 是一个工具感知的联合调度框架：其价值接口把近期工具就绪度、带时间衰减的节点级缓存收益与 token 占用合在一起，再用动态规划在容量约束下联合选择并放置等待中的会话。

在 12 个「模型-负载-并发」设置上，相对每个指标评测到的最优 SOTA 基线：延迟最多降低 **26.8%**，TTFT 最多降低 **36.3%**，decode 吞吐最多提高 **29.5%**。这条线补上了一个空白——昨天那些智能体评测在算「做不做得对」，这篇算的是「排队与工具等待怎么吃掉吞吐」。

### 端到端 MXFP8 RL：更低的采样精度反而更容易对齐，但省的钱有门槛

`值得读 ★★★★★` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.34915](https://arxiv.org/abs/2610.34915)

低精度能让 LLM 的 RL 更便宜，但 RL 要求采样器与训练器**互相认同**。作者把端到端 MXFP8 RL 落进 verl（Megatron/Transformer Engine 训练，vLLM 与 SGLang 采样，dense 与 MoE 模型），在 B200 上用 Qwen3-8B 与 Qwen3-30B-A3B 量了三件事。

**一致性**：对 MXFP8 训练器来说，跑在训练器同一套网格上的采样器比更高精度的 BF16 采样器更一致——固定权重、同一引擎下，采样器一半线性层在网格上时 train-rollout KL 低 **11%**，全部在网格上低 **16%**，且检查到的同步权重与训练器的 FP8 前向权重逐字节相等。MoE 上，采样器用另一套网格的 FP8 流水线，从第一步起 KL 就是同网格流水线的**两倍**。但若不量化 KV 缓存，端到端 BF16 仍一致 **2.5–10 倍**。**速度**：MXFP8 训练带来每 micro-batch 的固定开销、省下每 token 的成本，因而在 dense 设置下大约要超过 **4.5k tokens/micro-batch** 才回本——「什么时候更快」是个有门槛的答案，不是无条件加速。

<h2 id="cat-auto-driving">自动驾驶</h2>

### Dream2Assist：给共享控制加一个会推断意图的世界模型，让人愿意接手而不是被覆盖

`值得读 ★★★☆☆` ｜ `影响力 ★★★☆☆`

**来源**：[arXiv:2610.34650](https://arxiv.org/abs/2610.34650)

共享控制里的辅助智能体面对双向难题：既要主动对齐人的意图，又要足够**可读**，让人能理解并流畅地实时响应。Dream2Assist 是一个面向紧耦合共享决策的基于模型强化学习框架：在循环状态空间世界模型上扩展出意图推断，配合虚拟对弈（fictitious co-play）训练的辅助策略，去预判并支持离散的人为目标，而**不覆盖人的主导权**。

论文另一半篇幅给了落地：把世界模型策略安全、省资源地变成真实系统所需的完整部署流程，尤其是通过策略筛选与奖励重构来弥合 sim-to-real-human 这段差距，并把这一步嵌进迭代的人机界面设计。验证规模也说明了这点：三项人的被试实验加一次车载初步部署，覆盖两个性质不同的场景——高速竞速（N=30）与意图更丰富的城市驾驶。

<h2 id="cat-safety">安全与对齐</h2>

### 第三方评测 DeepSeek V4.1 Flash：34 个基准，并给出三条对开放权重模型的要求

`值得读 ★★★★☆` ｜ `影响力 ★★★★☆`

**来源**：[arXiv:2610.35671](https://arxiv.org/abs/2610.35671)（[HF Papers](https://huggingface.co/papers/2610.35671)）

闭源发布通常伴随完整 system card，开放权重模型在前沿风险上得到的审视明显更少。这篇独立评测针对 DeepSeek V4.1 Flash-1017（相对 V4 换了架构、扩大训练、智能体能力更强），依据 **EU 通用目的 AI 行为准则**设计，覆盖 34 个基准（含 5 个自研套件），维度是评测诚信、失控与有害操纵；比对方式符合 AEF-1 标准，对照对象包括 V4.1 Flash、更早的 V4 系列以及 GPT-6 Astra、GPT-5.6 Sol、Gemini 3.8 Flash 等闭源系统。

结论是改进与隐患并存：V4.1 Flash-1017 相对 V4 一代有实质性安全提升，若干维度逼近或追平领先的闭源基线，但仍有值得关注的具体行为。三条建议里有一条正好接住今天的其他线索——**最终的轮次输出与终态检查不足以发现失控行为，部署需要覆盖推理轨迹与动作日志的过程级可观测性**；另两条是把安全评测并入增量发布（安全会随小版本漂移甚至回退），以及公共基准会激发强烈的评测意识并受数据污染威胁，因此可信的前沿评测必须建设私有基准。
